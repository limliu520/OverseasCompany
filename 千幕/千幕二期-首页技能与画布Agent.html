千幕二期 · 首页技能与画布 Agent

版本 2.0 · 2026-10-09 · 适用端：千幕 Web 画布。沿用一期已确认的桌面工作台，本期不另做一套移动端交互。

版本目的

一期画布要求用户自己建节点、写提示词再点生成。不会搭流程的人，从一句想法到可生成的镜头之间断掉了。

本期用首页技能和画布右侧 Agent，把创作分镜、剧情短片接到同一张画布上。模型负责写文案和准备节点。图片、视频、配音仍由用户确认费用后才提交供应商。

要解决的问题：技能发送后能进入对应会话；分镜文案和剧本文案能落在节点上并单独计费；媒体生成不会在用户未确认时打到上游。

业务对象是短剧、短视频创作者。预期结果是：发送后画布上出现本次模式对应的节点和文案；文案费用在发送时结算；媒体费用只在确认卡或节点生成按钮提交后结算。

观察指标：技能发送后的画布打开率、文案生成成功率、媒体确认后的生成转化。本期不设定数值目标。

AG-01

首页用技能发起

功能逻辑

用户在首页画布输入区选择「创作分镜」或「剧情短片」，写上正文或放上已传完的附件，然后发送。系统创建一个项目、一条会话，打开画布并展开右侧 Agent。这条会话从发送时锁住对应模式。

业务规则

  • 两个技能共用一套入口。每份草稿最多一个。再选另一个就替换，不清空正文和附件。
  • 只选技能不能发送。正文和已上传完成的附件有一样即可。
  • 一次发送只创建一个项目。创建失败时保留首页输入。
  • 点「新建画布」只进空项目，不发起技能会话。
  • 若这次发送会生成文案，发送即预留文案点数。首页预计积分包含这次文案费用，不包含尚未确认的媒体费用。

页面交互

技能来自「技能」菜单、输入 /、以及输入条上的两个标签，状态一致。发送成功后离开首页，进入新画布。

异常

  • 文案点数不足：不创建项目，不调用模型，保留输入，并说明差额。
  • 重复点击发送：只创建一次。
  • 项目已创建但跳转失败：提供进入该项目的入口，不重建。

数据流转

首页草稿（正文、技能、附件、主体引用）写入新会话。文案任务预留点数。成功后把文案写入模式规定的节点，并扣费。失败则释放预留，不留下空节点。

AG-02 · AG-03 · AG-04 · AG-06

会话、文案扣费与媒体确认

功能逻辑

创作分镜锁定后，模型写出分镜文案，直接放进一个视频草稿的提示词。不另建文本节点，也不按镜头拆成多张图片。文案写完即可在节点里改。生成这段视频前，对话里给出费用确认。

没选技能、但已经能看出要图片或视频时，先准备对应草稿，再走同一张费用确认。由模型新写的文字，按文案规则在发送时扣费。

业务规则

  • 分镜文案、剧本文案、镜头文案都扣费。用户点击发送即确认这次消耗，不再弹确认卡。
  • 文案与媒体都是：提交时预留，成功再扣，失败把预留还回。
  • 用户在节点里手改已有文字，不另扣一次生成费。要求模型重写，则这次发送再扣一次文案费，仍不弹卡。
  • 图片、视频、配音必须出现确认卡，或由节点上的生成按钮提交。二者是同一次提交，点了节点按钮不再多问一次。
  • 确认之后不能取消已经打给供应商的任务。只有最新一张未确认的媒体卡片可以点。
  • 同一条会话不更换模式。要换技能，新建会话。

页面交互

顶部可切换本画布会话、新建会话、展开或收起。收起、切换、离开页面都不取消已提交任务。确认卡写明节点、数量、提示词摘要和点数，提供取消与确认。取消不提交，已写上画布的文案保留。

异常

  • 文案生成失败：释放预留，不留空节点，对话说明原因，允许用户再次发送。
  • 媒体点数不足或参数不合法：确认按钮不可用，并说明原因。已有节点保留。
  • 重复确认：只产生一次媒体提交。
  • 断网或刷新：向服务端查询真实状态。不断网直接当成失败，也不因此退回一笔仍在处理的预留。

数据流转

发送 → 预留文案点数 → 模型返回文案 → 写入视频节点提示词 → 成功扣费。之后用户确认媒体 → 预留媒体点数 → 提交供应商 → 成功扣费并回写该节点；失败释放预留，保留旧结果。已提交的媒体任务保存提交时的输入，后来改提示词不影响它。

AG-05

剧情短片

功能逻辑

发送后先生成一篇剧情，写入一个文本节点。这篇剧情按文案扣费，发送即确认。用户可在对话或节点里修改，修改直接落在这个文本节点上。手改不扣费；让模型重写则再扣一次文案费。

用户确认剧情之后，才按当前剧情创建一个视频草稿，并把剧情文本连到该视频上。确认剧情不扣费，也不提交供应商。生成视频仍要费用确认。

业务规则

  • 确认剧情之前不创建视频节点。
  • 视频还没提交时又改了剧情：文本直接更新，视频提示词跟着改，不用重新确认剧情。生成仍要费用确认。
  • 已经提交的视频不被这次修改覆盖。

页面交互

剧情写在文本节点和对话里，用户点确认剧情后，画布上出现视频节点和连线。费用确认的交互与创作分镜的视频确认相同。

异常

  • 剧情正文为空时不能确认剧情。
  • 剧情文本节点已被删除：提示节点已删除，不自动重建。
  • 连线不符合一期规则：不建立这条线，视频节点上的已有内容保留，并说明原因。

数据流转

发送 → 剧本文案预留并写入文本节点 → 成功扣费。确认剧情 → 创建视频节点，提示词取自当前剧情，并记录来自该文本节点的引用。媒体确认之后的预留、扣费、回写与 AG-06 相同。

AG-07

没选技能时的类型

功能逻辑

这条会话不进入创作分镜或剧情短片。用户的话已经写明要视频、图片或文字时，直接按该类型继续。看不出来，或只有附件没有说明类型时，先让用户在对话里选视频、图片或文本。选定之前不建节点，也不扣费。

业务规则

  • 不由模型替用户选定类型。
  • 选定视频之后，不再追问要不要先写大纲。
  • 选定文本：之后的文案生成按发送扣费，并直接写入文本节点。
  • 选定图片或视频：先准备草稿，再走媒体费用确认。

页面交互

三个选项为视频、图片、文本。点选相当于用户的一次明确输入，会话继续，不新建项目。

异常

用户不点选而发送了一句仍然看不出类型的话：再次给出这三个选项，不扣费，不建节点。

数据流转

类型选择只写入当前会话，作为下一步调用文案或媒体工具的条件。不单独产生扣费记录。

AG-08 · AG-09

引用、上下文与面板

功能逻辑

模型每一轮只看见当前会话的对话、本会话创建的节点，以及用户 @ 进来的节点和主体。点选画布上的节点，不会把它加入会话。新建会话不带上一条的节点。画布上的节点还在，只是新会话看不见。

用户 @ 了已有图片，话里又在做视频时，不规定必须当成首帧。连不连、连成什么用途，由模型决定，并遵守一期连线规则。

业务规则

  • 引用认节点 ID 和主体 ID。名称可重复。重名时必须点选一个，模型不能自己挑。
  • 首页 @ 只列主体。画布 @ 列当前画布的节点和主体，可按名称搜索。
  • 删掉输入框里的标签，不删除节点或主体。
  • 「暂无可用结果」的节点可以引用和修改。要拿它的成品当参考时拒绝，并说明还没有结果。
  • Agent 不能删除节点或断开连线。
  • 已有空白会话时，再点新建会话会打开那条空会话，不额外堆一条空会话。

页面交互

面板可展开、收起。顶部切换「本画布会话」。收起后再次打开，恢复当前会话、未确认的媒体卡片和任务状态。

异常

  • 引用的节点已删除：对话显示「节点已删除」，不自动重建。
  • 连线校验失败：不建立该线，不改已有内容。
  • 整理文案尚未结束时，输入区不可再发送。媒体已经提交、正在生成时，可以继续输入，但不能对同一个节点再次提交。

数据流转

@ 写入本条消息的引用列表，绑定 ID。工具只能改这份列表和本会话已创建的节点。会话切换只更换模型可见的材料和聊天记录，不改画布，不取消任务。
