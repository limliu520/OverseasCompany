版本目的 / 需求背景

登录、项目、账号权限、采集与文章主链路已有独立 PRD。本期补齐运营端「壳层」：登录后落地的工作台、消息中心、平台公告，以及全局帮助与反馈（含 Admin 配置与处理）。目标是让人一眼知道今天要关注什么、系统发生了什么、不会用时能问、有问题时能反馈到对内后台。

业务对象是已登录的主账号与子账号。工作台统计与异常的数据范围沿用《登录 / 子账号 / 权限》FZ-A-12：负责项目 + 本主账号 TG 公共池；平台公告全员可见。帮助内容与用户反馈由方舟 Admin 维护与处理，运营端只消费与提交。

三条信息通道必须分清：平台公告是 Admin 人工宣发；消息中心是产品 / 系统自动写入的事件流；工作台「状态与异常提醒」只展示当前仍未恢复的异常态。反馈提交进入 Admin 列表处理，不在工作台挂反馈待办。

本期集中写清规则与上线文案；截图后补。交互可对照 refactor-demo，以本稿规则为准。

本期不做：工作台待办列表、工作台反馈工单跟进块、工作台快捷操作区、零项目欢迎弹窗、侧栏菜单逐步引导、登录页演示角色选择。登录、改密、退出见账号 PRD。

FZ-W-01

页面壳与顶栏问候

功能逻辑

用户登录并完成账号 PRD 规定的验证后，默认进入工作台。有「工作台 · 概览」权限时，页面自上而下为：新手教程卡（满足 FZ-W-05 显示条件时）→ 数据概览 → 第二行左右两列「状态与异常提醒」与「平台公告」。顶栏左侧为问候语，右侧为「消息中心」入口与当前用户区（用户区能力见账号 PRD）。

所有角色共用同一套工作台布局。看见哪些指标、异常、教程模块，由菜单权限与 FZ-A-12 数据范围决定，不按「主账号壳 / 子账号壳」拆两套页面。

业务规则

1. 布局

  • 第一块：新手教程（条件见 FZ-W-05）；不满足时整块不占位。
  • 第二块：数据概览（FZ-W-02）。
  • 第三块：左「状态与异常提醒」（FZ-W-03），右「平台公告」（FZ-W-04）。宽屏两列，窄屏上下堆叠，左异常在上。
  • 工作台不展示待办列表、反馈工单列表、快捷操作芯片区。

2. 顶栏问候文案

  • 格式固定为：{问候}，{显示名}（中文逗号，逗号后无空格或有一空格均可，上线统一为「问候，显示名」中间无空格以外的多余符号）。
  • 问候按时段（按用户本地时区时钟）：
    • 0:00–11:59：「早上好」
    • 12:00–17:59：「下午好」
    • 18:00–23:59：「晚上好」
  • 显示名取当前登录账号资料中的显示名；显示名为空时回落为登录名。
  • 问候只出现在工作台顶栏。其他业务页顶栏使用该页标题（如「项目管理」「TG 采集」），不复用本问候句。

3. 权限入口

  • 「工作台」侧栏入口全员默认可见（与账号 PRD 一致），不出现在可取消勾选里。
  • 无「工作台 · 概览」时走 FZ-W-06，不渲染上述三块业务内容。

页面交互

  • 进入工作台：顶栏左展示问候；右展示「消息中心」（见 FZ-M-01）。
  • 刷新页面：按当前时刻重算问候；显示名取最新资料。
  • 侧栏点「工作台」：回到本页，保留浏览器常规刷新行为即可。

异常

  • 显示名与登录名皆空（数据异常）：问候退化为仅时段词，如「早上好」；同时应修复账号资料，不另弹窗。
  • 会话失效：按账号 PRD 回登录页，不停留在半截工作台。

数据流转

前端读取会话中的显示名 / 登录名与本地时钟生成问候。布局模块各自拉数：概览与异常受 FZ-A-12 过滤；公告全员；消息未读数来自消息服务。

FZ-W-02

数据概览

功能逻辑

数据概览给人当日运营体感：昨日采集与转化类 KPI、当前积压量，以及辅助看趋势的近 7 日采集、链路转化、昨日项目贡献。模块标题固定为「数据概览」。卡片按当前账号菜单权限裁剪：没有对应菜单权限的指标不出现，而不是整块隐藏概览。

业务规则

1. 数据范围

  • 项目相关数字只统计负责项目；另含本主账号 TG 公共池上可汇总的采集类数据（与 FZ-A-12 一致）。
  • 「当前待审素材」只计本组来源且处于待审核的素材（与 FZ-A-11 一致）。
  • 平台公共素材池的全平台总量不进入本模块。

2. KPI 卡片（有权限才出现）

  • 有 TG 采集查看权限：「昨日 TG 采集」，单位「条」。
  • 有网站采集查看权限：「昨日网站采集」，单位「条」。
  • 有素材查看权限：「昨日收到素材」「昨日素材通过」，单位「条」；以及「当前待审素材」，单位「条」。待审大于 0 时用警示强调样式。
  • 有文章查看权限：「昨日进入文章」「昨日已推业务端」，单位「篇」；以及「当前待处理稿件」，单位「篇」。待处理大于 0 时用警示强调样式。

3. 附加面板

  • 有 TG 或网站采集权限：展示「近 7 日采集」折线，图例为「TG」「网站」。
  • 有素材或文章权限：展示「链路转化」漏斗（收到 → 通过 → 进文章 → 已推等，按可见权限裁剪段）。
  • 有采集或项目列表权限：展示「昨日项目贡献 · Top3」；无贡献数据时文案「暂无项目贡献」。

4. 空态

  • 当前权限下没有任何 KPI 可展示时，概览主区文案：「当前权限下暂无可汇总指标」。

页面交互

  • KPI 与面板默认只读，本期不要求点击跳转（若后续加跳转须在修订中写清目标页）。
  • 近 7 日折线悬停：显示该日 TG / 网站数值提示条。
  • 进入工作台或刷新：按最新统计重算；不提供本模块独立「刷新」按钮。

异常

  • 统计接口失败：主区 Toast「数据概览加载失败，请稍后重试」；已渲染内容可保留上一次成功结果，若无缓存则显示「当前权限下暂无可汇总指标」。
  • 部分面板失败：失败面板内文案「加载失败」；其他面板照常。

数据流转

后端按账号 id、负责项目列表、主账号 id 聚合昨日与近 7 日指标。前端按菜单权限决定渲染哪些卡片与面板。待审 / 待处理为实时计数，昨日类指标按自然日（运营端约定时区，默认 UTC+8）切日。

FZ-W-03

状态与异常提醒

功能逻辑

本模块只展示「当前仍未恢复」的异常态，帮助人去修，不是历史流水。标题固定「状态与异常提醒」。与消息中心的关系见 FZ-M-03：异常发生时消息中心记一条事件；未恢复期间本列表持续展示；恢复后本列表移除该条，本期不因此自动再发「已恢复」消息。

业务规则

1. 纳入范围

  • 采集号异常：负责项目或公共池相关采集号处于断开、不可用、受限、登录失效等非正常连接态。
  • 频道异常：采集或分发频道体检为失败或无法判定（如 not a member、BROKEN、UNKNOWN）。
  • 路由异常：TG 路由健康失败，可并入频道异常展示或单独类型「路由异常」，同一对象勿重复两行。
  • 网站采集异常、内容通道级异常：在产品判定为「当前未恢复」时可进入本列表。
  • 不纳入：已恢复的历史；采集完成、推送成功等成功态；纯统计积压（待审条数走概览，不进本表）。

2. 列表字段

  • 列：异常对象、类型、原因、紧急度；行末操作「查看」。
  • 类型文案枚举：采集号异常、频道异常、路由异常、网站采集异常、稿件异常、素材异常；无法归类时用「{来源名}异常」。
  • 原因：展示当前状态说明或体检错误摘要，如「当前状态：已停止」「体检超时，结果无法判定」。

3. 紧急度

  • 对用户只展示三级中文标签：「紧急」「优先」「一般」。界面不展示 P0 / P1 / P2 字样。
  • 紧急：采集号不可用、频道 BROKEN 等须马上处理。
  • 优先：体检 UNKNOWN、部分降级可用等须尽快处理。
  • 一般：可排队处理的异常。
  • 排序：先按紧急 → 优先 → 一般；同级内按类型名称排序。首屏宜能同时看到不同紧急度样例时，可采用「各级先各取一条再接剩余」的混排，但紧急度标签语义不变。

4. 权限与范围

  • 无对应菜单权限的异常不展示（例如无 TG 权限不展示采集号 / 频道异常）。
  • 子账号只看负责项目 + 本主账号公共池相关异常。

5. 空态与分页

  • 无数据：文案「暂无状态或异常提醒」。
  • 工作台内紧凑分页：每页 5 条；展示「共 N 条 · 每页 5」与上一页 / 下一页。

页面交互

  • 点「查看」：进入该异常对应业务页（通常 TG 采集、网站采集、项目对接或文章列表），并尽量定位到相关项目 / 对象。
  • 点异常对象行本身：本期不额外响应，以免与「查看」重复；以「查看」为准。
  • 分页：上一页 / 下一页；到边界时按钮禁用。

异常

  • 「查看」目标页当前账号无菜单权限：不跳转，Toast「当前账号没有此功能权限」，停留工作台。
  • 目标对象已恢复或不存在：仍进入目标列表页，Toast「该异常已恢复或不存在」。
  • 列表加载失败：文案「状态与异常提醒加载失败，请稍后重试」。

数据流转

列表由采集号状态、频道 / 路由健康、网站与通道等实时态聚合。同一对象同一未恢复原因只保留一行。恢复后行消失。消息中心是否曾写入事件不影响本表是否展示。

FZ-W-04

平台公告摘要

功能逻辑

工作台右侧展示平台公告摘要，让人不用进列表也能看到最近宣发。标题「平台公告」。内容来自 Admin 已上架公告（FZ-N-02）。与消息中心、异常列表不混排。

业务规则

  • 最多展示 3 条，按发布时间倒序。
  • 每条展示：标题、摘要一句、发布时间；重要公告带「重要」标签；未读带未读圆点。
  • 全员可见，不按项目过滤。
  • 无公告：文案「暂无公告」。
  • 模块头右侧链文案：「全部公告」，进入 FZ-N-01 列表页。

页面交互

  • 点某条摘要：进入该公告详情页。
  • 点「全部公告」：进入公告列表。

异常

  • 摘要加载失败：模块内「公告加载失败，请稍后重试」；「全部公告」链仍可点。
  • 点进详情时公告已下架：见 FZ-N-01。

数据流转

读取已上架公告前 3 条及当前账号已读状态。点进详情后的已读回写见 FZ-N-01。

FZ-W-05

新手教程

功能逻辑

新手教程是工作台顶部的一块引导，按当前账号菜单权限列出可学模块。点「去学习」进入独立静态演示页（逐步高亮说明），演示不写入真实业务数据。进度按账号维度持久化。当前账号可见模块全部完成后，整块教程卡从工作台消失，不提供收起 / 展开。

业务规则

1. 显示条件

  • 可见模块数 ≥ 1，且已完成数 < 可见模块数时显示。
  • 可见模块数为 0，或已全部完成：整卡不渲染、不占位。

2. 模块清单（有对应权限才出现）

  • 创建项目（需新建项目权限）
  • 水印、文章配置（需项目查看权限）
  • TG 采集配置（需 TG 采集查看权限）
  • 网站采集配置（需网站采集查看权限）
  • 素材管理（需素材查看权限）
  • 文章管理（需文章查看权限）
  • 子账号与授权（需子账号管理查看权限）

3. 卡片文案

  • 标题：「新手教程」
  • 说明：「按你的权限逐步认识方舟 · 已完成 {done} / {total}（全部完成后本卡自动消失；每项为独立演示页）」
  • 未完成项右侧：「去学习」；已完成项右侧：「再看一次」；已完成项序号位显示完成标记。
  • 序号从 1 起按当前可见列表顺序编排。

4. 演示页规则

  • 演示页为独立页面，预填示意数据，确认 / 保存类操作不落真实项目、采集、素材库。
  • 步骤内编辑类弹窗：点遮罩不关闭，须点明确按钮（与全局弹窗规则一致）。
  • 完成该模块学习路径终点时，将该模块记为已完成，并回到工作台。
  • 用户中途退出演示：可不记完成；再次可从工作台进入。
  • 「再看一次」：可再次进入演示，不取消已完成标记。

页面交互

  • 点整张模块卡或「去学习 / 再看一次」：进入对应演示页。
  • 演示页内「下一步 / 完成 / 退出」等：按该演示页步骤文案执行；完成终点回工作台并刷新教程进度。

异常

  • 进入演示后权限被收回：演示可结束并回工作台；该模块从可见列表移除。
  • 演示页资源加载失败：Toast「教程页加载失败，请稍后重试」，提供返回工作台。

数据流转

进度存「账号 id → { 模块 id: true }」。可见列表 = 模块定义 ∩ 当前菜单权限。全部完成则工作台不再请求展示该卡。

FZ-W-06

无权限空态

功能逻辑

账号能进侧栏「工作台」，但没有「工作台 · 概览」能力时，不展示概览、异常、公告摘要与教程，改为整页说明。

业务规则

  • 标题文案：「当前账号无工作台权限」
  • 说明文案：「请联系主账号开通「工作台 · 概览」后再访问。」
  • 顶栏问候与消息中心仍可按壳层展示；本空态只替换内容区。

页面交互

  • 本空态无主操作按钮；用户通过侧栏前往其有权限的页面，或联系主账号改权限。

异常

  • 权限中途被开通：刷新或再次进入工作台后走正常 FZ-W-01 布局。

数据流转

仅依据会话菜单权限判断；不请求概览统计。

FZ-M-01

消息入口与未读

功能逻辑

消息中心承载系统自动提醒。工作台顶栏右侧提供「消息中心」文字入口与未读角标。有新的未读消息时，可在右上角弹出粘性提醒条，与页内短 Toast 区分开。

业务规则

  • 入口文案：「消息中心」。
  • 未读数 > 0：显示角标；1–99 显示数字；超过 99 显示「99+」。未读为 0：角标隐藏。
  • 本期以顶栏为正式入口；不强制再在侧栏挂二级「消息中心」。
  • 粘性弹窗规则见 FZ-M-03。

页面交互

  • 点「消息中心」：进入消息列表页（FZ-M-02）。
  • 弹窗点「查看」：进入该消息关联业务页或消息中心，并将该条标为已读。
  • 弹窗点关闭：关闭弹窗；该条本账号不再自动弹出；关闭不等于已读。

异常

  • 未读数拉取失败：角标隐藏，不阻断进入消息中心。

数据流转

未读数 = 当前账号可见消息中 status=未读 的条数。弹窗关闭状态按「账号 + 消息 id」记录。

FZ-M-02

消息列表

功能逻辑

消息中心页展示当前账号可见的全部消息事件，按时间倒序，支持分页与已读未读区分，并可跳到相关业务页。

业务规则

  • 排序：时间倒序，新在上。
  • 分页：全局列表翻页规范——左「每页显示」20 / 50 / 100（默认 20）；右「共 N 条 · 共 M 页」+ 页码。不用无限滚动。
  • 每条至少含：类型 / 级别、标题、时间、正文摘要；未读有可视区分。
  • 空态文案：「暂无消息」。
  • 可见范围见 FZ-M-03。

页面交互

  • 点一条消息：进入关联业务页（有 href 时）；同时标为已读。若无关联页，则仅展开或进入详情并标已读。
  • 换每页条数：页码回到 1。
  • 页内可提供「全部标为已读」：确认后将当前账号可见未读全部标已读，Toast「已全部标为已读」。

异常

  • 列表加载失败：Toast「消息加载失败，请稍后重试」，页内「暂无消息」或保留失败说明。
  • 关联页无权限：Toast「当前账号没有此功能权限」，消息仍标已读，停留消息中心。

数据流转

读消息服务按账号过滤后的事件流。已读写回该账号已读集合。不与公告已读共用一套存储。

FZ-M-03

消息规则与范围

功能逻辑

本条定义消息中心写什么、不写什么，以及和平台公告、工作台异常态、页内 Toast 的边界。开发按本表落事件，产品按本表验收「该不该有一条消息」。

业务规则

1. 三块通道

通道 来源 装什么 不装什么
平台公告 Admin 人工配置 维护通知、产品说明、使用指引；可标重要 业务流水、采集 / 推送结果、号掉线
消息中心 系统自动写入 状态变更事件 + 异常发生事件 Admin 宣发文
右上角消息弹窗 同消息中心 最新一条未读且未关闭过弹窗的摘要 不当唯一入口；不自动消失
工作台状态与异常提醒 当前未恢复的异常态 要人处理的持续异常 已恢复历史、成功态通知

2. 应写入消息中心的类型

凡对象状态变化且运营需要知情，落一条消息。

类型 触发时机 文案要素 建议跳转
采集完成 网站 / TG 一轮采集成功结束 源名称、新增条数、进入何队列 素材或对应采集页
采集已开始 手动或自动开始采集 源 / 采集号、项目 采集页
采集已停止 用户停止或系统停采 原因、会话是否保留 TG / 网站采集
采集失败 任务失败结束 源、失败原因摘要 采集页
转编辑完成 素材确认转编辑成功 素材标题、目标项目 文章列表
媒体处理完成 转编辑后媒体处理完成进入待编辑 稿件编号 / 标题 文章编辑或列表
文章推送成功 推送到项目内容通道成功 标题、项目 文章列表
文章推送失败 单篇推送失败 标题、失败原因 文章列表失败态
内容通道已接通 项目对接待接通 → 已接通 项目名 项目详情 / 对接页
频道异常 源 / 分发频道体检失败或无法判定 频道、角色、项目或公共池、错误摘要 TG 采集
采集号异常 采集号断开、不可用、受限、登录失效等 号名称、状态、影响 TG 采集
路由异常 路由健康失败 源→目标、采集号、错误 TG 采集
网站采集异常 站点配置失败、接入中断、任务反复失败等未恢复前的发生事件 站点名、原因 网站采集
推送通道异常 内容通道回调失败、凭证失效等通道级问题 项目、错误 对接页 / 文章

3. 明确不进消息中心

  • Admin 平台公告正文与重要标记（走公告）。
  • 纯 UI 操作结果（保存成功、复制成功等）→ 页内 Toast，可短时自动消失。
  • 工作台统计数字变化本身（如待审 +1）不单独刷消息；有明确业务事件（如采集完成）时再发。
  • 同一异常在未恢复期间的心跳探测：不重复刷消息。仅在「首次成为异常」或「原因 / 状态文案发生变化」时再写一条。
  • 本期异常恢复后不发送「已恢复」消息；恢复只体现为工作台异常列表移除。

4. 与异常态对照

消息中心 状态与异常提醒
时间性 事件流，历史可查 当前态，未恢复才在
成功态 有 无
异常 发生时记一条 未恢复则持续展示
入口 顶栏消息中心 + 弹窗 工作台模块

5. 账号可见范围

  • 主账号：本主账号下全部项目及相关公共池事件。
  • 子账号：仅负责项目相关事件 + 本主账号 TG 公共池相关事件。与己无关项目的消息不投递、不展示。

6. 粘性弹窗

  • 有「未读且本账号未关闭过该条弹窗」的消息时，展示时间最新的一条。
  • 不自动消失；无倒计时。
  • 点关闭：仅关弹窗，不标已读；本条不再自动弹出。
  • 新消息到达：替换当前弹窗内容（顶掉）。
  • 点「查看」：跳转并标已读。

页面交互

  • 本条为规则定义，无独立页面按钮。弹窗按钮文案：「查看」、关闭为「×」。

异常

  • 事件写入失败：业务主流程不因消息失败而回滚；需可观测日志，必要时补偿重试。
  • 弹窗展示时用户已进入消息中心并读掉该条：关闭弹窗或同步移除。

数据流转

各业务域在状态变更成功后异步投递消息事件（类型、标题、正文、级别、关联跳转、项目 / 主账号范围）。消息服务按接收账号过滤入库。已读、弹窗关闭为账号维度侧车状态。

FZ-N-01

全部公告与详情

功能逻辑

运营端提供公告列表与详情，只读消费 Admin 已上架公告。用于维护通知与产品说明，不承载业务流水。

业务规则

  • 列表按发布时间倒序；重要公告展示「重要」。
  • 未读 / 已读按账号记录；未读在列表与工作台摘要上可区分。
  • 空态：「暂无公告」。
  • 详情只读展示标题、时间、重要标记、正文。
  • 全员可见。
  • 列表翻页同全局规范（20 / 50 / 100）。

页面交互

  • 点列表标题：进详情；进入详情即标为已读。
  • 详情「← 全部公告」：回列表。
  • 工作台「全部公告」：进本列表。

异常

  • 公告不存在或已下架：详情页文案「未找到该公告。」，并提供按钮「返回全部公告」。
  • 列表加载失败：Toast「公告加载失败，请稍后重试」。

数据流转

读已上架公告。已读写入账号公告已读表。与消息已读分离。

FZ-N-02

Admin 公告配置

功能逻辑

在方舟 Admin 维护平台公告。运营端无编辑入口。重构 Demo 不做 Admin 页；本稿只定能力与字段口径。

业务规则

  • 字段：标题（必填）、摘要（选填，供工作台摘要）、正文（必填）、是否重要、上架状态、发布时间。
  • 仅「已上架」对运营端可见。
  • 下架后运营端列表与摘要不再展示；已打开的详情按 FZ-N-01 不存在处理。
  • 重要标记仅影响展示，不改变投递范围（仍全员）。

页面交互

  • Admin 提供新建、编辑、上架、下架。编辑类保存须点明确按钮；点遮罩不关闭未保存表单。
  • 删除若提供：须二次确认，确认文案说明运营端将不可见。

异常

  • 标题或正文为空保存：提示「请填写标题」或「请填写正文」，不保存。
  • 保存失败：提示「保存失败，请重试」。

数据流转

Admin 写入公告主数据与上架状态。运营端工作台摘要与列表只读已上架记录。

FZ-H-01

运营端帮助与反馈

功能逻辑

全局提供「帮助与反馈」入口，打开同一面板，内含两个 Tab：「帮助」与「反馈」。帮助用于按当前页给出常见问题与对话检索；答不上来时引导用户切到反馈。反馈提交见 FZ-H-02。帮助问答内容来自 Admin 配置（FZ-H-03）。

业务规则

  • 入口位置：侧栏账户区域上方（全局壳层常驻），文案「帮助与反馈」。
  • 默认打开「帮助」Tab。
  • 帮助区包含：对话区、当前页「猜你想问」快捷问题、底部输入框。
  • 快捷问题随当前页面变化，并按菜单权限过滤没有权限的条目。
  • 猜你想问标签文案：「猜你想问 · {当前页名称}」。
  • 输入框占位：「问「{当前页名称}」相关问题…」。
  • 首次打开可有一条助手欢迎语，说明可点下方问题或切到反馈。
  • 匹配不到问题时，助手回复引导去「反馈」Tab，完整说明可反馈缺陷 / 界面 / 建议等。

页面交互

  • 点入口：打开面板，默认帮助 Tab。
  • 点「帮助」/「反馈」Tab：切换；不关闭面板。
  • 点快捷问题：用户气泡展示问题，助手气泡展示答案；若有跳转且当前账号有权限，附「去处理 →」。
  • 输入后点「发送」或回车：同上匹配逻辑。
  • 点关闭「×」：关闭面板。
  • 点面板外遮罩：关闭面板（帮助面板无可保存草稿的编辑主路径时允许遮罩关闭；若反馈 Tab 已输入未提交，见下条）。
  • 反馈 Tab 已填写未提交时：点遮罩不关闭，须点「×」或提交；点「×」可关闭（本期不强制二次确认未提交内容，若关闭则清空未提交草稿）。
  • Esc：非点选问题位置模式下关闭面板；规则同关闭。

异常

  • 帮助配置未加载到：快捷区可空；对话答「暂时无法获取帮助内容，请稍后重试或切换到反馈」。
  • 发送空内容：不发送，不报错或 Toast「请输入问题」。

数据流转

打开时按当前路由页键拉取该页可见问答。检索优先当前页配置，可回落全局词条（若 Admin 配置了全局）。不在帮助对话里写业务库。

FZ-H-02

反馈提交内容

功能逻辑

用户在反馈 Tab 提交问题或建议。系统默认附带当前页整页截图元数据；用户可再点选页面问题位置，附带定位信息。提交后进入 Admin 反馈列表（FZ-H-04），不在工作台生成待办或工单行。

业务规则

1. 字段

  • 反馈类型（必选，单选）：「缺陷」「界面」「建议」「其他」。默认「缺陷」。
  • 反馈说明（必填）：多行文本，占位「描述遇到的问题或建议」。
  • 整页截图：默认附带，说明文案：「提交时默认附带当前页整页示意截图。若再点选问题位置，会额外带上该区域定位与现场数据，方便研发对照。」
  • 问题位置：可选。未点选则只带说明 + 整页截图。

2. 点选问题位置

  • 按钮文案：「点选问题位置」。进入点选后顶栏提示：「点击页面上有问题的区域」，右侧「取消」。
  • 进入点选时暂时收起帮助面板，进入页面点选态；Toast「请点击页面上有问题的区域」。
  • 点中有效区域：记录标签、id、可见文本、路径与研发对照提示；Toast「已记录问题位置」；回到反馈 Tab。
  • 点选态下 Esc 或「取消」：不写选区，Toast「已取消点选」，回到反馈 Tab。
  • 已有选区时显示「清除选区」与摘要「已点选问题位置」。
  • 点选忽略帮助面板自身与点选层控件。

3. 提交

  • 主按钮：「提交反馈」。
  • 成功且未点选：Toast「已提交反馈（说明 + 整页截图）」。
  • 成功且已点选：Toast「已提交反馈（整页截图 + 问题位置）」。
  • 成功后：清空说明、恢复类型为缺陷、清除选区、回到帮助 Tab 并关闭面板。
  • 提交中按钮禁用，防止重复提交。

页面交互

  • 类型按钮：点选切换，互斥高亮。
  • 「清除选区」：清定位，摘要隐藏。
  • 编辑反馈过程中点遮罩：不关闭面板。

异常

  • 说明为空点提交：Toast「请填写反馈内容」，不关闭。
  • 提交接口失败：Toast「提交失败，请稍后重试」，保留已填内容与选区，按钮恢复可点。
  • 截图生成失败：仍允许提交文字；Toast「截图生成失败，已仅提交文字说明」或失败则整单失败——本期定为：截图失败时仍提交文字与类型，Toast「截图未能附带，已提交文字反馈」。

数据流转

写入反馈单：类型、说明、页面路径、提交人、提交时间、整页截图、可选点选定位、状态=待处理。投递 Admin FZ-H-04。运营端工作台不读此列表。

FZ-H-03

Admin 帮助配置

功能逻辑

方舟 Admin 维护帮助问答内容，供运营端帮助 Tab 展示与检索。可按页面绑定，也可配置全局通问。运营端无配置入口。

业务规则

  • 词条字段：问题文案、答案文案、绑定页面（可多选或全局）、可选跳转路径、启用状态、排序、可选权限码（无权限则运营端不展示该条）。
  • 仅「启用」词条对运营端生效。
  • 同一页面多条按排序展示；运营端「猜你想问」展示条数建议不超过 8 条，超出按排序截断。
  • 禁用或删除后，运营端立即不可见；已打开的会话不强制清历史气泡。

页面交互

  • Admin 列表支持筛选：页面、启用状态、关键词。
  • 新建 / 编辑为表单；点遮罩不关闭；保存 / 取消明确按钮。
  • 保存成功提示「帮助词条已保存」。

异常

  • 问题或答案为空：提示「请填写问题」或「请填写答案」。
  • 保存失败：「保存失败，请重试」。

数据流转

Admin 写入词条库。运营端按当前页键 + 权限过滤拉取。不经过工作台。

FZ-H-04

Admin 反馈处理

功能逻辑

方舟 Admin 提供反馈处理能力：在同一套列表中查看用户提交、处理待处理项，并查询已处理等历史记录。运营端只负责提交，不在业务工作台跟进状态。

业务规则

1. 列表

  • 字段：提交时间、提交人（显示名 / 登录名）、主账号、反馈类型、说明摘要、来源页面、是否含截图、是否含点选位置、状态。
  • 状态：「待处理」「已处理」。
  • 默认筛选：待处理在前；支持按状态、类型、时间范围、关键词筛选。
  • 已处理记录保留在同一列表，用状态筛选查看，不另拆无关业务系统；若 Admin 信息架构需要「记录」子 Tab，数据源仍是同一反馈单，仅默认状态=已处理。
  • 翻页同 Admin 列表规范；无则 20 / 50 / 100。

2. 详情与处理

  • 可查看完整说明、整页截图、点选定位与现场路径。
  • 待处理可执行「标为已处理」。可填处理备注（选填）。
  • 已处理后状态=已处理，记录处理人、处理时间、备注。
  • 本期不要求回写处理结果到运营端工作台；若需通知提交人，另开迭代。

页面交互

  • 点行进详情。详情内「标为已处理」须确认或主按钮明确提交。
  • 成功 Toast「已标为已处理」。
  • 编辑备注类弹层：点遮罩不关闭。

异常

  • 重复处理已处理单：Toast「该反馈已处理」，保持已处理。
  • 反馈不存在：Toast「反馈不存在或已删除」，返回列表。
  • 截图资源缺失：详情标注「截图不可用」，其余字段仍可处理。

数据流转

读 FZ-H-02 写入的反馈单。处理动作更新状态与处理审计字段。列表与「记录」视图共用该表。
