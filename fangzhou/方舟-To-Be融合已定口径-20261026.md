# 方舟 To-Be · CMS / 外站融合已定口径（2026-10-26）

> 来源：10-26 与开发会议 + 后续产品对齐；现网能力对照 `fangzhou 源代码`（及姜清《项目配置按站点类型清单-20261026》）。  
> 性质：**重构口径落档**。保留能力、去掉冗余双形态；**不是**按线网 UI 原样搬家。  
> Demo / 代码实现：等本档无异议后再改；本文件不替代研发设计，只冻结产品边界。

---

## 0. 重构总原则（必须遵守）

1. **同一能力只留一套产品形态。** 现网「CMS 项目管理 + CMS 账号发稿」与「外站发布」本质都是：采到料 →（可选编辑/媒体处理）→ 推给业务方。重构后归口为 **项目管理（一项目 = 一套内容通道）**。
2. **保留功能能力，不保留重复外壳。** 线网用来核对「有没有这项能力」；新路径可以换交互、换配置落点、换对接方式，**不能 silently 删掉业务仍需要的能力**。
3. **字段取并集，不取交集。** A 有 B 无 → 留；B 有 A 无 → 留；两边都有 → 去重成一项；两边都无 → 无。
4. **开关原则。** 任一边现网有开关 → 新配置做开关；两边都是固定行为 → 可继续固定（或按类型默认，见类型表）。
5. **上限就高。** 例如视频水印层数：项目侧可配 3 种、外站现网上限 2 → 新产品按 **3** 设计（实现需水印服务支持；现网外站代码写死 `MAX_VIDEO_WATERMARKS = 2`，属实现债）。
6. **Admin 与业务端分工。** 业务端不配的（如写稿画像）可留在老方舟 Admin；业务端要操的必须在项目管理 / 子账号里说清。

## 2. 站点类型（已定）

代码现状：`CMSProject.site_type` 仅 `chigua` | `video`（见 `models/editorial.py`）；外站无类型字段，短剧靠开关组合。

| 类型 | 对齐现网 | 内容侧 | 媒体侧要点 |
| --- | --- | --- | --- |
| **瓜站（内容站）** | 现 `chigua` | 进内容通道才走文章配置 + AI；TG 分发不经 AI（直推） | 默认可含视频；**不展示**「推送全部分集」 |
| **视频站** | 现 `video` + **51短剧（AI 文 + 1 视频）归此类** | 同上 | 一稿 **一个** 视频；正文去图等现网能力保留并在统一链路补齐 |
| **短剧站** | 蜜果 / KiteDrama 等外站形态；**剧集站 = 短剧站** | **不配文章模板**；内容通道侧 **不生成文章**；TG 仍可直推 | 去水印/加水印/切片/分集等；一稿 **多视频（分集）** |

创建时只选类型 → 按类型显隐模块；配置项全集 = 原项目配置 ∪ 原外站配置。

## 3. 出稿路径（已定 · 按分发去向，不按项目手选）

### 现网怎么判路

| 形态 | 怎么进 | 正文怎么来 |
| --- | --- | --- |
| **CMS 项目**（专属站） | 频道绑 `dedicated_project_code`；加工完可转编辑 / 开自动流 | **一律 AI + 文章设置**；项目上**没有**「原文直推」开关 |
| **外站** | 频道绑 `external_site_id`；加工完建发布任务 | 站点级 `generation_mode`：`ai` / `raw` / `none`（运营在外站配置里手选） |
| **TG 分发** | 公共池素材走 `routing_rules` | **不经** AI；素材原样按路由推 TG。专属站 / 外站素材**跳过** TG 分发 |

结论：现网**不是**「同一项目同时具备 TG 直推 + CMS 编辑再推、再让人二选一」。  
是三条**互斥归属**（专属 CMS / 外站 / 公共池 TG），各自走各自的生成策略。外站才有「手选 AI/原文/不生成」。

### To-Be（融合后）

取消「项目配置里手选 AI / 原文直推」。路径由**这条素材要去哪**决定（泳道图 S6）：

| 分发去向 | 出稿行为 | 对应旧能力 |
| --- | --- | --- |
| **TG 频道** | 不经内容编辑、不跑文章 AI；按路由直推 | 旧「原文直推 / 直接推送」+ TG 分发 |
| **内容通道**（瓜/视频） | 进编辑 → AI/模板（±自动流）→ 通道推送 | 旧 CMS 主路径 + 外站 `ai` |
| **内容通道**（短剧） | **不生成文章**；标题/摘要凑合取素材，推媒体为主 | 旧外站 `none` |
| ~~外站独立站点~~ | 并入项目内容通道 / 对接规范；不再单独挂「外站 generation_mode」 | — |

**对方分类**（旧 `push_config.category`）：不做项目固定字段。栏目若对方仍要 → 发稿时选，或对接规范字段，**待技术**。

自动推送（原 `auto_editorial` / `auto_push` 去重）：项目级意向；**内容通道接通后才生效**。列表：外侧可有「提交」「编辑」；进编辑后仍有「提交」。

## 4. 配置并集要点（已定 + 显隐）

### 4.1 对接（项目级，方舟规范）

保留能力（来自外站为主）：站点代码、名称、接口地址/前缀、签名密钥、启用、备注、推送相关开关等。  
**删除形态：** `CMSAccount` 用户名密码谷歌码登录；`ExternalSiteAccount` 对方发布账号。  
**替换：** 我方凭证 + 业务方对接；子账号 **CMS 标识** 随推送携带。

### 4.2 内容生成

| 项 | 瓜 | 视频 | 短剧 |
| --- | --- | --- | --- |
| 出稿路径 | **不按项目手选**；按分发去向：TG→直推不经 AI；内容通道→编辑+AI | 同左 | 内容通道侧固定不生成文章 |
| 文章模板/提示词/篇幅/改写/文案链接 | 要（进编辑时） | 要 | **不用** |
| 对方分类（旧外站 category） | **不做项目固定字段**；栏目若需要 → 发稿时或对接规范另定（待技术） | 同左 | 同左 |
| 写稿画像 | **业务端不做**，留 Admin | 同左 | 同左 |

### 4.3 配置模块归位（交互强制：同类同处）

创建步进与详情 Tab **按主题成块**，禁止把同一主题拆到两个 Tab：

| 模块 | 收纳内容 |
| --- | --- |
| **封面** | **只保留宽×高一套**；生成与推送共用。旧外站 `cover_aspect` **废弃**（比例由宽高本身体现） |
| **水印** | 二级切换两功能：**去源水印**（独立开关页）/ **添加水印**（四类叠加）；不再塞在同一屏混读 |
| **视频规则** | 必须含视频、切片 m3u8、最短时长 |
| **推送规则** | 推送方式（= 外站 auto_push：自动 / 待人工）+ 短剧「推送全部分集」等；瓜/视频不展示分集 |
| **文章模板** | 结构模板 / 自定义提示词 / 篇幅 / 文案链接（短剧跳过） |

| 项 | 口径 |
| --- | --- |
| 必须含视频 | 三站都会有视频；**默认开** |
| 封面尺寸 | **三站都要；全局必填**；生成出图 / 推送 / 自定义画框同一套像素 |
| 封面比例（旧外站） | **不做**；勿再单独配 `cover_aspect` |
| 去源水印 | 开关归水印模块（与叠加水印同 Tab） |
| 切片 | 归视频规则 |
| 视频水印 | 支持至 **3** 种（就高）；归水印模块 |
| 推送全部分集 / 分集标题 | 来自现网**推送站点** `push_config`；**短剧要、默认开**；瓜/视频 **不显示、默认关**；归 **推送规则**。分集标题可选（英文站建议填） |
| 最短时长 30s、最多 50 集 | **全局上限**（现网 `EXTERNAL_PUBLISH_MIN_VIDEO_SECONDS` / `MAX_EPISODES`）；推送站点弹窗不配；**项目侧也不单独配** |

### 4.4 推送规则与互动

| 项 | 口径 |
| --- | --- |
| 推送方式 | = 现网外站「推送方式」/`auto_push`：自动推 vs 待人工；接通后生效。步骤名「推送规则」（不再叫「自动推送」） |
| AI 评论 | **项目维度**（能力保留；前台预览/校验进 AI 评论模块，项目上「前台地址」可不再当主字段） |
| 跑马灯 | **废弃**（代码 `marquee_text` 仅存储展示，无消费方） |

### 4.5 网站采集

现网：`website_collection` 绑 `external_site_id(s)`（外站 ≤5），**不能**直接绑 CMS 项目。  
To-Be（已定 · 2026-10-27 收口）：

- 在 **网站采集配置** 里绑 **项目**（承接原「绑外站」能力；外站已并入项目管理后，目标就是项目）。
- **瓜站 / 视频站 / 短剧站** 均可绑定；一站一种类型，只绑**同类型**项目，最多 **5** 个。
- 不做「仅短剧」限制。

## 5. 审核（已定 · 重构后模型）

现网事 A：用 CMS 账号登录对方，**拉取** UGC，探测接口，写回（`REVIEW_FEATURE_PROBES` 等）。  
现网事 B：编辑部内素材/文章流程权限。

### To-Be

| | 事 A：业务方 UGC（帖/评） | 事 B：方舟生产内容 |
| --- | --- | --- |
| 流入 | 对方 **接口推送** 到方舟 | 方舟内部流程 |
| 处理 | 方舟 AI + **子账号审核权限** | 方舟流程 + **同一套子账号权限** |
| 流出 | 结果 **写回** 对方 | 留在方舟（通过/驳回/可提交等） |
| 对方 CMS 登录 | **不需要** | **不需要** |

- 子账号：CMS 标识（推送身份）+ **审核相关权限**（A/B 均可按权限项拆）。  
- 写回所需为项目级出站配置（URL/签名等），**不是**业务方登录号。  
- 不再依赖「保存 CMS 账号时探测对方有没有审核接口」作为主路径。

### 7.2 明确删掉的是「重复形态」，不是能力本身

| 删除的形态 | 能力如何还在 |
| --- | --- |
| 业务端维护 CMS 登录账号发稿 | 改为方舟规范推送 + CMS 标识 |
| 外站「发布账号」登录对方 | 同上 |
| 「外站」独立导航/表 | 能力进项目管理 |
| 跑马灯字段 | 无消费者，可弃 |
| 用 CMS 账号拉 UGC 审核 | 改为对方推送 + 方舟审 + 写回（能力升级，非删除审核） |

### 7.3 与口径一致但代码尚未具备（实现债，非口径回退）

| 债 | 说明 |
| --- | --- |
| 无 `short_drama` 类型 | 需新增类型及显隐矩阵 |
| CMS 链路无 `generation_mode` | 并集后项目级三态 |
| CMS 文章设置不作用于外站 AI | 融合后应统一可读模板（能力补齐） |
| CMS 一稿一视频 vs 外站多集 | 短剧走多集；视频站保持一视频——编排要按类型分支 |
| 网站采集只绑外站 | 改为绑项目（全类型）；原外站目标由项目承接 |
| 外站水印最多 2 | 产品就高到 3，需服务与校验一起改 |
| 审核仍偏 CMS 拉取 | 事 A 要改成推送入站 + 权限模型 |
| Demo 仍含外站挂载 | 口径锁定后再整体重构 Demo |

### 7.4 结论（过码结果）

- **口径与「功能有没有」不冲突：** 并集项都能在 CMS 侧或外站侧（或两者）找到代码落点。  
- **冲突的是双形态与对接方式：** 正是本轮要二合一优化的对象。  
- **不能删的是链路能力**（直推、AI 编辑、分集、水印、自动推、审核、网站采短剧等）；**可以删的是**第二套账号外壳、第二套站点模块、无消费字段。  
- 按当前重构思路推进 **成立**；落地时按类型补齐第五节能力差，而不是退回两套产品。
