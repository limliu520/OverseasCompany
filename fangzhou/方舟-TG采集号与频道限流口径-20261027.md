# 方舟 · TG 采集号（Userbot）与频道限流口径（2026-10-27）

> 来源：产品对话整理（采集号归属、限流、频道/Bot 数量上限、Admin 可配）。  
> 性质：**已定边界落档**，供评审；**本稿先不改 Demo / 研发实现**。  
> 与旧口径冲突时：**以本稿为准**（尤其废止「Userbot 放在业务端全局配置、账号级共用资产」）。

---

## 1. 对话结论（人话版）

### 1.1 为什么不能做成「全局共用 Bot」

- TG 采集号是**运营侧专属配置**，不是全公司随便拿去用的公共号。
- 若 A 的 Bot 被 B 拉进别的群/频道，下载并发一高就容易**限流甚至封号**。
- **TG 号本身不要共用乱挂**。素材采下来之后「能不能共、什么范围共」→ **放到采集专题再议**，本稿不写死。

### 1.2 归属维度（已定）

| 问法 | 结论 |
| --- | --- |
| 每个运营？每个子账号？ | 可理解为**业务账号体系下的资源**，但配置落点按 **项目** |
| Bot 放哪？ | **按项目维度划分**：在项目里配置 / 绑定采集号 |
| 一个项目几个 Bot？ | **一个项目可以配置多个 Bot** |

业务端侧栏「全局配置 → Userbot」这种「全账号共用池、各项目来挑」的形态要改掉（见 §4）。

### 1.3 限流到底是什么问题（已定理解）

- 主要风险：**同一个 Bot 进了太多频道**，多频道同时出料时 Bot **并行下载** → 限流 / 封号。
- 分流手段（对话中提到、产品侧认可的方向）：
  1. 开会员（平台侧能力，业务端不展开）
  2. **同一素材群挂多个 TG 号分流采集**
  3. **同一频道不要被多个项目各自再挂一套号**（见下条互斥；与「素材池怎么共用」分开，后者归采集专题）

### 1.4 频道 × Bot × 项目 规则（已定）

| 规则 | 口径 |
| --- | --- |
| 一 Bot → 多频道 | 允许，但要有上限 |
| 一频道 → 多 Bot | 允许（用于同群分流），但要有上限 |
| 一项目 → 多 Bot | 允许，**最多 10 个（暂定）** |
| 采集 vs 分发 | TG 号**既可以采也可以发**，角色上**不强制**「必须同时挂采集频道 + 推送频道」；可以只挂采集、不挂推送（或反之，按业务需要） |
| 跨项目抢同一频道 | **项目 1 的 TG 已加入频道 A 后，项目 B 再配 TG 去加频道 A → 不允许**，给明确提示（勿重复进群叠风险；**不**在本稿展开素材池共用细节） |
| 上限默认值 | 见 §2；**做成可配置**，默认先按本次拍板，后续可调 |

### 1.5 谁配上限（已定）

- **Admin 后台**：配置「一频道最多几个 Bot」「一 Bot 最多进几个频道（采集+分发合计）」「一项目最多几个 Bot」等。
- **业务端**：只按 Admin 下发的上限使用与提示，不在业务端再开一套「改上限」的管理。

## 2. 数量上限（本次先定 · 可配置）

| 维度 | 默认上限（已定起步值） | 说明 |
| --- | --- | --- |
| **同一频道**上的 Bot 数 | **最多 5 个** | 够分流下载；含该频道上承担采集和/或分发角色的号（不另拆两套频道上限，除非以后再拆） |
| **同一 Bot** 加入的频道数 | **采集频道 + 分发频道合计 ≤ 10** | 不是「采集 10 + 分发 10」；是**总数 10** |
| 一项目可配 Bot 数 | **最多 10 个（暂定）** | 同样放 **Admin 全局配置**，业务端只读上限做校验 |

后续按线上封号/限流情况再调数字；调数走 Admin，不必改业务端产品结构。

### 5.1 「业务端是否保留只读总览」是什么意思？

指：去掉「全局配置 → Userbot」作为**配置入口**之后，还要不要在业务端留一个**只能看、不能当共用池去绑**的页面——例如「本业务账号下所有项目用了哪些 Bot」的汇总列表。

- **做**：方便主账号巡检，但要写清「只读、不能从这里往项目乱挂」，否则容易又变回「全局池」心智。  
- **不做（建议默认）**：Bot 只在各项目里管，侧栏不再出现独立 Userbot 菜单。

这是入口形态选择题，不是限流规则本身。

### 5.2 「最终提示文案」是什么意思？

指：规则触发时，界面上**具体弹哪一句字**（Toast / 对话框全文）。

例如跨项目互斥，语义已定是「别的项目已经用号进了这个频道，你这边不能再进」，但上线到底写：

- 「该频道已被其他项目的采集号加入，请勿重复进群」，还是  
- 「频道 A 已被项目「××」占用，本项目无法再加入」  

这类**完整句子**可以等写 Demo / PRD 交互时再定稿；本稿只锁**什么情况下要拦、要说清什么意思**。

## 7. 入口建议：项目配置太深 vs 侧栏会不会乱（产品方案）

### 7.1 问题

- 项目详情 Tab 已经很多（水印 / 片头片尾 / 文章 / 图片视频 / 对接 / 通道·Bot / 推送 / 可选…），**藏得深、找得到但烦**。
- 若把 Bot、频道、水印等**都**拉到侧栏 → 菜单乱、和「归属在项目」打架。
- 若**全部**只藏在项目里 → 日常运维（断线重连、看哪个号挂了）成本高。

### 7.2 原则（建议采用）

1. **归属不变**：Bot / 频道仍归**项目**；侧栏若出现，只是**快捷工作台**，不是第二个「全局资产池」。
2. **按「使用频率 × 是否跨项目巡检」决定谁上侧栏**，不是按「配置项多不多」。
3. **一侧栏一类事**；进页后用「项目筛选」收束，避免菜单爆炸。
4. **低频、强项目上下文的配置**继续留在项目详情（或项目内「设置」子页），不要上侧栏。

### 7.3 谁上侧栏、谁留项目里（建议）

| 能力 | 建议入口 | 理由 |
| --- | --- | --- |
| **TG 采集号（Bot）连接/断开、看状态、进退频道** | **侧栏可有「采集号」** + 项目内仍可进 | 高频运维；断线要快找到。列表**按项目分组或必选项目筛选**；新建必须选归属项目 |
| **频道（采集/分发）与 Bot 的挂载关系** | 跟 Bot 同一工作台，或项目「通道」里 | 和 Bot 强绑定，不必再单独占一个侧栏一级 |
| **水印 / 片头片尾 / 文章提示词 / 图片视频规则 / 推送规则** | **只留项目内** | 低频、改完很少动；上侧栏只会乱 |
| **开发对接（App ID / 通道接通）** | 项目内为主；列表「待接通」可跳进项目对接 Tab | 按项目一次接通，不是日常巡检 |
| **子账号与岗位** | 侧栏「全局配置」保留 | 真正的账号级，不是项目配置 |
| **采集记录 / 异常 / 素材审核**（若有） | 侧栏「采集」下 | 运营日常工作台；与「项目配置」分离 |

### 7.4 Bot 双入口怎么做才不乱（推荐形态）

**推荐：一个侧栏「采集号」，但心智是「按项目管的 Bot 工作台」。**

- 侧栏：**采集** 分组下挂「采集号」（不要塞进「全局配置」和子账号并列，避免「账号资产」误解）。
- 进入后：
  - 顶栏 **项目筛选**（默认「全部项目」仅用于浏览；**新增 / 连接影响进群的操作必须先选项目**）。
  - 列表卡片上固定露出：**归属项目**、连接状态、挂了几个频道。
  - 点进某 Bot → 管理该 Bot（仍显示项目名；换项目归属若允许，要走明确流转，默认**不允许随便改归属**，免变成共用池）。
- 项目详情「通道 / 采集号」：**同一套数据**的项目视角（只看本项目的 Bot），可「添加采集号」「管理频道」；与侧栏是同一实体，不是两套库。

**不推荐：**

- 侧栏再做一个「真正的全局 Bot 池」供各项目勾选（已否决）。
- 水印、文章、推送各占一个侧栏一级（菜单必炸）。
- 只有项目深处、侧栏完全没有 Bot（日常断线成本高）。

### 7.5 项目配置本身怎么「变浅」（配合侧栏）

即使有了侧栏 Bot，项目详情仍建议**收束 Tab**：

1. **概要区快捷入口**（详情顶卡）：如「采集号与频道」「内容通道对接」「水印与片头」——跳到对应区块，减少在 Tab 里盲找。
2. **Tab 合并命名**（候选，实现时可再收）：
   - 「媒体与水印」= 水印 + 片头片尾 + 图片视频规则（都是出片形态）
   - 「采集与通道」= 本项目 Bot + 频道（与侧栏采集号打通）
   - 「内容与推送」= 文章管理（非短剧）+ 推送规则
   - 「对接与可选」= 开发对接 + 可选功能
3. **创建向导**只保留必配最短路径；细项创建后再进项目改。

### 7.6 侧栏会不会乱？——控制手段

- 一级菜单**不按配置项拆**，按**工作对象**拆：项目 / 采集（含采集号）/ 编辑 / 互动 / 账号权限。
- 「采集号」挂在**采集**下，不挂「全局配置」。
- 其他项目配置**不上侧栏**；深度靠项目内分组 + 顶卡快捷，不靠加菜单。

### 7.7 入口形态（2026-10-27 产品拍板）

| 项 | 结论 |
| --- | --- |
| Bot 归属 | **项目**（一项目最多 10 Bot，Admin 可配） |
| 侧栏「全局配置 → Userbot」 | **已去掉**；采集号只在项目 Tab「TG 采集号」配置（旧 `userbots.html` 跳转项目列表） |
| 项目详情 Tab 收束、顶卡快捷 | **先不动** |
| 项目内「TG 采集号」 | **展示 + 入口 + 可新建号**；频道列表只读；**不加/不解绑频道** |
| 侧栏「采集 → TG 采集」 | **唯一操作台**：连接/断开、**拉取频道**、加入频道、解绑、监听；与项目展示同一套数据 |
| 连接 vs 监听分层 | **连接/断开**放左侧采集号旁（运维级，后续可单独授权）；**开始/停止监听**放详情顶栏（日常采集启停）。不把断开沉到项目管理里操作，避免两处都能改会话 |

**操作唯一原则（2026-10-27 补定）：** 同一类操作只在一处可直接做；别处可展示、可跳转入口；新建弹窗可多处（如创建项目 / 项目详情均可新建采集号）。

**拉取频道（产品保留，不可删）：** 现网 `sync-from-telegram`——把「本号在 Telegram 里已经进过、方舟列表还没有」的群同步进方舟。与「加入频道」（填 @/邀请链接去新进群）互补：人在 TG 里先进群 → 用拉取；人从方舟发起进群 → 用加入。Demo 无真 TG 时用模拟数据演示同步效果，**按钮与能力保留**。

### 7.8 公共池（2026-10-27 补定）

| 项 | 结论 |
| --- | --- |
| 定位 | **与业务项目同级**的工作上下文（不是某个项目下的开关） |
| 用途 | 配置公共池 TG 号；走 **TG→TG 路由**；**非项目归属**的料进公共池 |
| 入口 | 侧栏「TG 采集」顶栏「项目切换」：`公共池 | 各业务项目` |
| 与业务项目差异 | 业务项目：料进本项目内容通道，**无**站点绑定主路径、**无**路由；公共池：有路由，不做内容通道项目配置 |
| 同频道互斥 | 公共池与业务项目之间仍互斥（勿重复进群） |
