# 方舟 · To-Be 信息架构与权限草案（只动结构，不动能力）

> 版本：v0.4 · 2026-10-14  
> 原则：**现有功能能力不删不改口径**，先打散再按业务结构重组；权限先定可见范围。  
> 终态交付：可开发 PRD（含流程、逻辑、原型），本草案是结构与权限底稿。  
> 系统 Admin = 平台侧看全部（下表不再逐行打勾）。表中只标 **项目 Admin / 业务**。  
> 标记：`●` 可见可用 · `○` 默认不可见 · `△` 可见但只读/仅授权范围 · `?` 待拍板  
> **核心四块（已与开发对齐）**：**接入 · 配置 · 工作台 · 权限**  
> **v0.4**：接入方=项目 Admin；配置拆「核心路径 / 可选单功能」；工作台分层；调度/舆情拆分原则；新增反馈；账号-项目关系待定写入

## 1. 重组思路

### 1.1 离开「功能中心」，按四块收

不再用：采集中心 / 内容中心 / AI审核中心 / 外站 / 管理中心 作为一级心智。

| 块 | 解决什么 | 谁为主 |
| --- | --- | --- |
| **接入** | 注册、开户、教程、密钥、对外接口；把项目接上方舟 | 项目 Admin |
| **配置** | 核心路径必配 + 可选单功能按需开通 | 项目 Admin |
| **工作台** | 待办 + 统计；业务看自己的，Admin 看项目级更全 | 业务 / 项目 Admin |
| **权限** | 谁能配、谁能做、菜单按开通能力显隐 | 项目 Admin 管业务号 |

配套仍保留：**内容 / 审核**（日常操作面）、**平台设置**（仅系统 Admin）。

### 1.2 账号与开户链路（已定）

**接入方 = 项目 Admin**（不再单开「接入方」角色）。

```
用户注册账号
    → 该账号即「项目 Admin」
    → 可见「接入 / 配置」相关入口
    → 完成核心路径配置（时机见 §1.3 待定）
    → 再创建业务账号并授权
    → 业务账号进工作台做日常；可选能力按开通情况出现菜单
```

| 角色 | 范围 | 典型职责 |
| --- | --- | --- |
| **系统 Admin** | 全平台 | 接入治理、TG/全局策略、配额、跨项目排障、反馈处理后台等 |
| **项目 Admin** | 自助注册后的本账号/项目 | 接入与配置、建业务号、看项目级统计与全量待办；**不把配置甩给业务** |
| **业务** | 被授权的项目 + 能力切片 | 工作台（统计+待办）、内容/审核日常；**不配核心路径、不开通单功能、不建业务号** |

### 1.3 账号 ↔ 项目（待定，影响配置挂载点）

| # | 问题 | 选项 | 影响 |
| --- | --- | --- | --- |
| A | 一个 Admin 账号几个项目？ | ① 一账号一项目 ② 一账号多项目 | 多项目时：建业务号要**分配所属项目**；工作台要选当前项目 |
| B | 项目间数据？ | ① 完全隔离 ② 部分互通 | 列表默认过滤、跨项目统计是否存在 |
| C | 配置挂在哪？ | ① 全在项目 ② 部分在账号层 | 核心路径配置是「注册后」还是「建项后」做 |

> 拍板前：导航里「配置」同时预留账号层 / 项目层位置；正文默认按「**配置挂项目**」写，账号层只标 `?`。

### 1.4 配置两大块（已定思路）

#### （1）核心路径配置 — 每个项目必须

服务于 **爬取 → 加工 → 分发** 主链路。  
注册或创建项目时就要做完（具体挂在「注册后」还是「建项后」→ 等 §1.3）。

典型内容（能力不丢，入口收拢）：采集绑定、自动流、水印/模板、CMS、外站发布对接、主链路相关密钥/回调等。

#### （2）单个功能配置 — 可选、独立接入单元

附加小能力，**单独开通、单独配置、单独使用**；要则开，不要则菜单与接口都不露。  
开通后给：接入教程 + 对应接口（与核心路径同一套「接入」体验，但是按能力拆包）。

### 1.5 可选小能力汇总（生成 / 审核拆开）

> 除「社区帖子」现网偏「只有审核、没有生成」外，多数社区向能力是「生成 + 审核」成对出现；**用户审核只有审核**。

| 能力单元 | 生成 | 审核 | 说明 |
| --- | --- | --- | --- |
| AI 生成评论（站群文章评论） | ● | — | 原 AI评论运营 + 参数 |
| AI 审核评论（站群评论审） | — | ● | 原 AI评论审核 |
| AI 相关·社区评论 | ● | ● | 原社区评论侧；生成与审核都可开 |
| AI 相关·社区帖子 | ○ 现网无独立「生成」主路径 | ● | **现网只有审核向**；生成若以后要做再单开 |
| 用户审核 | — | ● | 仅审核 |
| 外站评论审核 | — | ● | 原 AI审核中心·记录；对接站+回调 |
| （其他扩展） | 按包 | 按包 | 能力市场等弱相关 → 系统 Admin 或后置 |

规则：

- **主流程（核心路径）**：每项目必须配置、必须使用。  
- **上表小能力**：按需开通；未开通 → 业务菜单隐藏、接口不可用。  
- 项目 Admin 开通某包后，再把对应菜单切片授给业务号。

### 1.6 调度中心 / 舆情中心拆分原则（已定）

现「调度中心」「舆情中心」不整坨保留。

| 原则 | 落到 |
| --- | --- |
| **业务用得上的** | 拆进业务侧模块：工作台统计、待办、内容/审核里能直接动手的指标与入口 |
| **业务用不上的** | 放进 **Admin 后台**（项目 Admin 的项目级看板，或系统 Admin 的平台设置） |

舆情若整体与日常运营弱相关 → 优先平台/Admin，不进业务默认导航。

### 1.7 工作台数据分层（已定思路）

| 面 | 是什么 |
| --- | --- |
| **业务工作台** | **统计 + 工作台**：待办为主，顺带展示**该业务账号自身**相关数据（处理量、待办数、失败数等） |
| **项目 Admin 后台** | 项目级更全的统计与健康度（全员/全队列、配置是否齐全、可选能力开通状态等） |

### 1.8 反馈（新增 · 重要）

| 项 | 说明 |
| --- | --- |
| 能力 | 任意界面可**快速截图 + 填反馈**；系统收集、处理、回复 |
| 为何做 | 替代群里反复口述；可记录、可观测、可闭环 |
| 权限 | 项目 Admin、业务均可提；系统 Admin（或指定运营）在后台处理回复 |
| 落点 | 全局入口（浮层/顶栏），**不塞进某一业务菜单深处** |

## 2. To-Be 导航结构（草案）

```
方舟
├── 【业务侧】
│   ├── 工作台                 ← 统计 + 待办（业务看本人数据）
│   ├── 内容
│   │   ├── 素材
│   │   ├── 文章
│   │   ├── 发布任务（外站）     ← 核心路径日常
│   │   └── 流水线（只读/例外，授权后）
│   ├── 审核（主链路相关）
│   │   └── 素材审核（人工/二次/垃圾/源水印等）
│   └── （可选能力 · 开通后才出现）
│       ├── AI评论（生成·运营）
│       ├── AI评论审核
│       ├── 用户审核
│       ├── 社区帖子（审核）
│       ├── 社区评论（生成/审核，按开通）
│       └── 外站评论审核
│
├── 【项目 Admin】
│   ├── 接入
│   │   ├── 接入向导 / 教程（核心路径 + 已开通可选包）
│   │   ├── 密钥与应用
│   │   ├── API / Webhook 文档
│   │   ├── 调用日志 / 沙箱
│   │   └── 配额与已开通能力
│   ├── 配置
│   │   ├── 核心路径配置        ← 每项目必配（爬取→加工→分发）
│   │   │   ├── 采集绑定 / 自动流
│   │   │   ├── 水印与文章模板
│   │   │   ├── CMS
│   │   │   └── 外站发布对接 …
│   │   └── 单个功能配置        ← 可选包：开通 / 参数 / 教程入口
│   │       ├── AI生成评论
│   │       ├── AI审核评论
│   │       ├── 社区评论（生成/审核）
│   │       ├── 社区帖子（审核）
│   │       ├── 用户审核
│   │       └── 外站评论审核
│   ├── 业务账号与权限           ← Admin 创建业务号（多项目时要绑项目 ?）
│   └── 项目数据看板             ← Admin 侧更全统计（调度中心里「业务用不上」的部分可落这）
│
├── 反馈                       ← 全局；全角色可提
│
└── 平台设置                   ← 仅系统 Admin
    ├── 接入治理（审批/配额/能力名单）
    ├── Telegram / Userbot / 路由 / 受保护源 …
    ├── 全局策略、广告规则、提示词、健康 …
    ├── 反馈处理台
    └── 舆情等弱相关（若保留）
```

说明：

- 「开放接入」不再写成与 Admin 平行的第四角色入口，而是 **项目 Admin 的「接入」区**。  
- 可选能力：配置在 Admin「单个功能配置」开通；使用面出现在业务侧对应菜单。  
- 调度中心：业务用的指标 → 业务工作台；其余 → 项目数据看板 / 平台。  
- 舆情中心：默认不进业务导航，进平台或 Admin（待拆细）。

### 2.1 核心路径 vs 可选能力（对照）

| 类型 | 是否每项目必须 | 配置入口 | 使用入口 |
| --- | --- | --- | --- |
| 核心路径（爬取→加工→分发） | 是 | Admin · 核心路径配置 | 工作台 / 内容 / 素材审核 |
| 可选单功能（上表各包） | 否 | Admin · 单个功能配置（开通+参数+教程） | 开通后才出现的业务菜单 + 对应 API |

### 2.2 AI / 社区能力落点（防和「外站审核」搞混）

| As-Is | 生成/审核 | To-Be |
| --- | --- | --- |
| AI评论 | 生成 | 可选包「AI生成评论」→ 配置在 Admin；使用在内容侧运营页 |
| AI评论·评论配置 | 配置 | 单个功能配置 · 该包参数 |
| AI评论审核 | 审核 | 可选包「AI审核评论」 |
| 社区评论 | 生成+审核 | 可选包，可拆开开通 |
| 社区帖子 | 现网以审核为主 | 可选包「社区帖子审核」；生成若补做再单开 |
| 用户审核 | 仅审核 | 可选包「用户审核」 |
| AI审核中心·记录 | 外站评论审 | 可选包「外站评论审核」 |

## 3. 权限总表

- **系统 Admin**：平台全量（省略）。  
- **项目 Admin**：本账号下项目（数量关系见 §1.3）；含接入、两类配置、建业务号、项目看板。  
- **业务**：仅授权项目 + 已开通且被授予的菜单；无配置区。

### 3.1 工作台

| 模块 | 项目 Admin | 业务 | 备注 |
| --- | --- | --- | --- |
| 业务工作台（统计+待办） | ●（可看项目全量或切到业务视角） | ● | 业务侧统计=**本账号**相关 |
| 项目数据看板 | ● | ○ | Admin 更全；承接原调度中心「非业务向」部分 |
| 待办·素材/二审/文章失败/外站待推送等 | ● | ● | 主链路待办；业务按授权 |
| 待办·可选能力转人工 | ● | ● | 仅已开通对应包时出现 |

### 3.2 内容 / 主链路审核

| 模块 | 项目 Admin | 业务 | 备注 |

## 6. 待拍板

### 6.1 账号与项目（优先）

1. **一账号一项目，还是一账号多项目？**  
2. 若多项目：业务账号是否必须绑定项目？工作台是否强制先选项目？  
3. **项目数据完全隔离，还是部分互通？**  
4. **是否存在账号层配置？** 核心路径挂在注册后还是建项后？

### 6.2 其它

5. 公共池 / TG 路由仍归系统 Admin？  
6. 自助注册闸门：公开 / 邀请 / 审批后才可生产调用？  
7. 旧「站点配置」表单与新接入向导：并行还是只维护存量？  
8. 业务能否改「未分发」规则？建议否。  
9. 系统 Admin 是否保留改任意项目 CMS 的后门？建议保留。  
10. 舆情拆完后，业务侧是否保留任何入口？默认否。
