## 0. 对本轮调整的产品判断（先读）

你提的方向大体对：**先有项目，再有项目配置；配置归一处；采集 / 编辑 / 互动三分开；账号独立管子账号。**  
下面是结合现网实测与访谈后，**不同意或建议改**的点——已写进后文结构。

| 你的想法 | 判断 | 本稿怎么处理 |
| --- | --- | --- |
| 接入向导 / 技术接入 / 密钥跟项目走 | **同意** | 全部收进 **项目管理 → 项目配置**，去掉顶级「接入」一级 |
| 注册→登录→创建项目→接入 | **同意** | 写入标准开户路径；「接入」= 配齐本项目配置（含技术向 + 底座） |
| 接入后剩采集 / 编辑 / 互动 三块 | **同意** | 三个一级（或三个「台」）；能力仍可按功能授权显隐 |
| 可选功能开通在项目里，开通后生成对应配置 | **同意** | 开通 + **该包参数配置**都在项目配置；互动菜单不再堆配置 |
| 所有配置都归项目配置，互动里不配 | **同意，且建议钉死** | 一次配置 vs 日常操作分离；互动 = 运营界面/看板 |
| 纯接入、无需二次确认 → 可做成看板 | **同意** | 见 §1.5 互动呈现原则 |
| 账号管理独立 | **同意** | 一级「账号管理」；Userbot 仍挂账号（养号），不挂项目 |
| 数据看板先留着、前期用不上 | **同意** | 挂项目管理下或隐藏入口，不进主路径 |
| 大菜单只要：项目 / 采集编辑互动 / 账号 | **基本同意，缺一块** | **建议保留「工作台」一级**（见下） |
| 网站采集、TG 采集配置也塞进「项目配置」？ | **不建议** | 仍放 **采集** 下：变更频、和审核/异常同一心智；项目配置只放「项目一次性能配齐、或可选包参数」 |

### 为何坚持留「工作台」

访谈与实测里，运营痛点是「今天要处理什么」分散在多菜单。若一级只剩项目 + 采集 + 编辑 + 互动 + 账号，人仍要自己拼待办。  
**工作台 = 跨模块待办汇总 + 轻量本人统计**，不是第四套业务，成本低、收益高。  
若你坚持菜单极简，退一步方案：工作台做登录默认页/顶栏入口，不占侧栏一级——但**不能没有**。

### 「项目配置」vs「采集里的配置」怎么划

| 放进 **项目配置 L2**（项目稳态 / 开包） | 放进 **采集等业务流 L3** | 放进 **账号资产 L1**（独立于项目） |
| --- | --- | --- |
| 基本信息、自动流、水印、模板、**内容通道**、可选包参数 | 网站采集实例、TG 绑定与参数、审核/异常 | Userbot/加频道、**外站站点主数据** |
| 技术接入、接入向导、本项目启用哪些外站 | 外站**任务**（编辑台） | 子账号与授权 |

原则：**L1 管资产本体；L2/L3 只引用 + 填本项目/本流字段。** 详见层级分析 §0。

## 1. 重组思路（v0.9）

### 1.0 三层挂载 + 配置/使用分离

| 层 | 装什么 | 导航落点 |
| --- | --- | --- |
| **L1 账号** | 子账号授权；Userbot/加频道；外站站点主数据 | 账号管理（**独立管理页**） |
| **L2 项目** | 底座、自动流、内容通道、技术接入、可选包、**启用**哪些 L1 外站 | 项目管理 · 项目配置 |
| **L3 业务流** | 网站采实例、TG 绑定、审核/编辑/外站任务/互动 | 采集 / 编辑 / 互动（**引用 L1 + 本流字段**） |

#### 配置权 vs 使用权（L1 资产）

| 权限 | 能做什么 |
| --- | --- |
| **配置权** | 进入账号层管理页；新增/编辑/删除 Userbot、外站站点等 |
| **使用权** | 在项目/业务流里**下拉选择**已有资产；无管理页、无改主数据 |

流内表单上的「新增/编辑」快捷：仅配置权可见。交互二选一（细化时定）：

- A. 跳转账号管理页（带返回）  
- B. 流内弹窗（调同一套保存接口）  
- 建议：简单新增用 B，复杂编辑用 A。

Userbot：**现网一 bot 多绑定** → L1；项目 TG 流只引用。

### 1.1 外部产品心智

```
注册/登录
  →（账号层）必要时养 Userbot、维护可复用外站资产
  → 创建项目
  → 项目配置（底座 + 技术接入 + 可选包）≈「本项目接入完成」
  → 日常：工作台 + 采集 / 编辑 / 互动（L3）
  → 账号管理贯穿
```

| 一级 | 解决什么 | 主层级 |
| --- | --- | --- |
| **工作台**（建议保留） | 今天要动手的事 | 跨 L3 聚合 |
| **项目管理** | 建项、项目配置（L2） | L2 |
| **采集** | 采源实例 + 主链路审核/异常 | L3 |
| **编辑** | 文章、修片、外站任务 | L3 |
| **互动能力** | 已开通包的运营/看板 | L3（配在 L2） |
| **账号管理** | 子账号、Userbot、（建议）外站资产 | L1 |

### 1.2 标准用户路径

1. **注册账号**（闸门待定）→ **登录**  
2. **创建项目**（此时才出现该项目的配置套件）  
3. **项目配置 / 接入**：底座（信息、自动流、水印、模板、**内容通道**、外站底座）+ 技术接入（密钥、文档、联调，待技术）+ 按需开通可选功能并填包内配置  
4. **账号管理**：加子账号、授功能、子账号可维护「CMS 标识」、（可选）养 Userbot  
5. **采集**：网站和/或 TG 配源并开采 → 料进本项目  
6. **编辑 / 自动流**：处理或跳过人工编辑 → **内容通道推送** / 外站等（推送带 CMS 标识；业务方自行发布）  
7. **互动**：仅开通的包出现；纯自动的看看板，要人审的进队列  

### 1.3 账号与菜单边界（不变）

外部同一套菜单，功能勾选显隐。开户主账号默认授齐建项与项目配置；子账号按需。  
方舟 Admin 仍为对内一套。

### 1.4 可选功能：开通在项目，配置在项目，使用在互动

```
项目配置 · 可选功能
  → 打开「AI 评论生成」
  → 自动出现该包配置项（条数、分散小时…）
  → 侧栏「互动能力」出现对应运营入口（或仅看板）
  → 子账号需另授「可用该包」才看见
```

**产品债务（须补）**：做「AI 评论」时必须补「评论预览」。前台地址预览入口已删，否则能力不完整；侧栏仍为 stub 时须明示本条，不可默默丢掉。

### 1.5 互动能力呈现原则

| 类型 | 产品形态 |
| --- | --- |
| 全自动、无人断点 | **看板**为主（量、成功率、失败数）；可不进操作队列 |
| 需人审 / 手动触发 / 确认 | **运营列表 + 操作**（通过/拒绝/触发） |
| 仅对接、业务从不进方舟点 | 可只留项目配置 + 调用日志，互动侧极简或隐藏 |

日常 Userbot 不在此代配；保留总览排障。

## 3. 权限（按功能）

绑项目 + 勾功能/合集。主账号默认：建项、项目配置、**L1 资产配置权**、账号管理。

| 类型 | 外部 | 方舟 Admin |
| --- | --- | --- |
| L1 资产**配置权**（Userbot / 外站主数据） | 勾了才 ● | 总览排障 |
| L1 资产**使用权**（流内选用） | 勾了才 ●（可与配置权分离） | — |
| 项目配置（含接入、可选包参数、启用外站） | 勾了才 ● | 统看 |
| 采集 / 编辑 / 互动运营 | 勾了才 ● | 可监管 |
| 子账号管理 | 勾了才 ● | 总览 |
| 平台策略 / 反馈处理 | ○ | ● |

例：只有「TG 采集使用权」的业务员 → 能在本项目绑已有频道并开监听，不能添加 Userbot。
