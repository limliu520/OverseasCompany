> 版本：v0.8 · 2026-10-15（菜单同 v0.8；泳道图见 v0.2）

## 0. 访谈结论（2026-10-15）入稿摘要

| 结论 | 对 To-Be 的影响 |
| --- | --- |
| 现状分工像资料/分发、编辑、审核 | **只作现状描述**。权限不按岗位固化，按功能授权，方便以后拆合 |
| 主路径：TG → 采集 → 编辑 → 发布 → **自有后台审发文** | 编辑是高频操作；发文审默认不进方舟主菜单 |
| 采集侧大量是配置，操作主要在素材审核 | **网站采集、TG 采集配置归业务人员**；不放在业务 Admin 独占区 |
| 网站采集对小站实用性低 | 功能仍在，可按项目少授、少露 |
| 理想态：配置 + 审核即可发，编辑可省略 | 编辑是功能而非必经岗位；自动流成立时编辑待办可为空 |
| 去水印差，更认修片 | 修片是独立功能，可授给做编辑的人 |
| 统计口径与班次对不上 | 工作台口径可配 |
| 配置运营自己做，技术偏权限 | 底座与开户归业务 Admin；采集配置由被授权的业务人员做 |
| SEO / 模型质量 | 结构留口，不靠菜单假装解决 |

**两类「审核」必须分清：**

| 名称 | 是什么 | 落点 |
| --- | --- | --- |
| **主链路审核** | 爬取→清洗→编辑→发布这条链上的质检（素材待审、二审等；发文后审多在自有 CMS） | 采集区里的**操作**，主要就是素材审核 |
| **互动/AI 审核** | AI 评论审、帖子审、用户审、外站评论审 | **可选功能**，与主链路审核分菜单 |

## 1. 重组思路

### 1.1 四块

| 块 | 解决什么 | 谁为主 |
| --- | --- | --- |
| **接入** | 注册、教程、密钥、对外接口 | 业务 Admin |
| **配置** | 分两层：项目底座 vs 采集配置 | 底座→业务 Admin；网站/TG 采集配置→被授权的业务人员 |
| **工作台** | 统计 + 待办 | 按已授功能出现待办 |
| **权限** | 按**功能**授权，功能可打成**合集**再组合 | 业务 Admin 授；方舟 Admin 统看 |

业务侧一级仍是 **工作台 / 采集 / 编辑 / 互动能力**，但显示与否看功能，不看岗位名。

### 1.2 账号与菜单边界

```
外部用户（同一套菜单）
  注册/首次登录的账号 = 业务 Admin（默认授齐：建项、配底座、建号授权等）
      → 再创建其他账号，按功能勾选（也可勾「创建项目 / 编辑项目」等）
      → 谁被勾了什么，谁就看见什么——不因「是不是 Admin」换一套导航

方舟 Admin（对内）
  → 多一套平台菜单；可统看全部外部账号
```

| 称呼 | 含义 | 菜单 |
| --- | --- | --- |
| **方舟 Admin** | 平台内部 | **对内菜单**（账号总览、平台 TG、全局策略、反馈处理…） |
| **业务 Admin** | 通常指开户主账号，或被授了建项/授权等管理功能的人 | 与业务人员 **同一套外部菜单** |
| **业务人员** | 被授权的执行账号 | 同上；只是勾选的功能更少时少见若干项 |

要点：菜单只有两套——**外部用户** / **方舟对内**。业务 Admin 与业务人员不是两棵树；「创建项目、查看项目、编辑项目、账号授权」等也是可勾功能，勾了就能进对应菜单。

### 1.3 功能授权（替代岗位）

授权单位是**功能**。若干功能可预先打成**功能合集**，创建账号时勾合集，也可拆开单授、多合集叠加。合集是快捷方式，以后加功能只加功能和合集，不新增角色。

| 功能（示例） | 性质 | 谁可被授 |
| --- | --- | --- |
| 网站采集配置 | 配置 | 业务人员 |
| TG 采集配置（本项目采哪些、怎么进项目） | 配置 | 业务人员 |
| 主链路·素材审核 | 操作（采集侧主要操作） | 业务人员 |
| 采集异常 / 未分发处理 | 操作 | 业务人员 |
| 文章编辑与发布 | 操作 | 业务人员 |
| 修片 / 媒体处理 | 操作 | 业务人员 |
| 外站发布任务处理 | 操作 | 业务人员 |
| AI 评论生成 / 评论审核 / 社区 / 用户审 / 外站评论审 | 可选功能 | 项目已开通后，再授给业务人员 |

预设合集只是默认组合，名称可改，**不是岗位**：

| 合集（示例） | 内含功能 | 说明 |
| --- | --- | --- |
| 采集 | 网站采集配置 + TG 采集配置 + 素材审核 + 采集异常 | 配置为主，审核为主要操作 |
| 编辑 | 文章编辑发布 + 修片 + 外站任务 | 可与「采集」合集同时授给同一人 |
| 互动 | 已开通的评论/帖子/用户等功能 | 按包再切 |

同一业务人员可以只拿合集里的一部分，也可以同时拿多个合集。

### 1.4 配置分给谁

| 配置 | 归属 | 说明 |
| --- | --- | --- |
| **网站采集配置** | 外部账号（独立功能） | **项目内**配置；与 TG 采集分开授权 |
| **TG 采集配置** | 外部账号（独立功能） | **项目内**绑定频道；平台 Userbot 归方舟 Admin；细则见泳道图 §5 |
| 自动流总开关、水印与模板、CMS、外站站点对接 | **业务 Admin · 项目底座** | 每项目一套；业务人员默认不改 |
| 可选功能开通（评论/社区等开不开） | **业务 Admin** | 开通后才能把对应功能授给业务人员 |
| 接入、密钥、建号 | **业务 Admin** | |

业务 Admin 可查看名下项目的采集配置（监管），日常填写由被授权的业务人员完成。

### 1.5 采集区：配置多、操作少

采集不是「一个岗位的工作台」，而是一组功能：

- **配置（主体）**：网站采集、TG 采集  
- **操作（少量）**：主要是 **主链路·素材审核**，外加采集异常/未分发  
- 流水线：可只读，便于对配置结果

### 1.6 两类审核、工作台、反馈、留口

- 主链路素材审核挂在采集操作里；互动审核在「互动能力」，未授权不出现。  
- 发文后审核默认在自有后台，方舟不做完整发文审台。  
- 工作台按**已授功能**出待办和本人相关统计；业务 Admin 看板是名下多项目、口径可配（跨天/班次）。  
- 反馈：全局可提，方舟 Admin 处理。  
- 留口：编辑可省略（只授配置+审核功能即可跑）；修片；SEO；模型效果不在菜单里解决。

## 3. 权限（按功能，不按岗）

外部账号：绑项目 → 勾功能或功能合集 → 菜单显隐。  
方舟 Admin：对内菜单 + 可查看全部外部账号（不替代外部日常授功能）。

| 功能类型 | 外部账号 | 方舟 Admin |
| --- | --- | --- |
| 采集配置 / 素材审核 / 编辑 / 外站任务 / 互动 | 勾了才 ● | 可监管 |
| 项目创建与底座编辑、账号授权、可选功能开通、接入 | 勾了才 ●（主账号默认有） | 统看 |
| 账号总览、平台 TG、全局策略、反馈处理 | ○ | ● |

## 5. 待拍板

1. 项目底座里还有没有也应下放的项（例如水印日常改、外站站点字段）？当前只明确下放 **网站采集配置、TG 采集配置**。  
2. 功能合集由谁维护默认包：平台预置，还是业务 Admin 可自建合集？建议先平台预置，Admin 只做勾选组合。  
3. 发文后审核是否永远站外。  
4. 统计口径谁可改。  
5. 自助注册闸门；公共池路由是否仅方舟 Admin。  
6. **技术接入**：接口清单、鉴权、沙箱与验收标准——**待技术评估后回填**泳道图 §3。  
7. **采集归属**：默认「源绑项目、料进项目」还是「账号级料池再分项目」？（建议前者；见泳道图 §4）  
8. 公共池+路由是否保留；同一 TG 频道能否绑多项目。

已定：一号多项目；称业务 Admin；按功能授权；**网站采集与 TG 采集为两个功能**；主链路审核 ≠ 互动审核；**外部同一套菜单**。  
已定/建议：**素材按项目归属**；**Userbot+加频道挂账号**；绑定与采集参数挂项目；账号多项目≠共享料池。
