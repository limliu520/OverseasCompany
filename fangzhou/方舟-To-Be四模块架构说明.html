方舟重构 · 目标架构四模块

给技术与业务对齐用：先看整体关系，再按模块看定位、菜单与流程。 外部用户共用一套菜单（按功能授权显隐）；方舟 Admin 为对内平台能力。 后续细化（页面 / 按钮 / 字段）将按这四块分别推进。

对齐草案 v0.8 · 泳道图 v0.4 入驻 = 项目一次性 · 配置 = 随业务常改 采集归属项目 · Userbot 挂账号

Overview

整体：四层怎么叠在一起

自下而上：平台治理支撑入驻 → 入驻把项目一次配齐 → 配置让采源与出口随业务调整 → 运营处理日常待办与三条分发。

01

方舟 Admin

定位：平台对内治理与排障，不替代业务日常配置与运营。

涉及菜单（对内）

账号与接入

  • 账号总览 · 业务 Admin / 业务人员 （管理员+业务账号 · 合）
  • 接入审批 · 配额与能力名单 （新）

策略与运维

  • 自动通过 / 质量门禁 （配置管理）
  • 广告过滤 · 提示词
  • 系统健康 · 任务管理 · 批量导入

其他

  • 反馈处理 （新）
  • Userbot 总览（排障）· 公共池路由 · 舆情

用户流程（平台侧）

  1. 治理开户 / 审批接入（若有生产闸门）
  2. 配置影响全站自动化的全局策略与提示词
  3. 监控健康、任务、跨账号 Userbot 异常
  4. 处理用户全局反馈并回复
  5. 公共池路由等例外能力（非默认主路径）

沟通重点

日常养号、加频道已下放到外部账号；Admin 保留总览与排障，避免再成为业务配置瓶颈。

交界：向下支撑「项目入驻」的开户与配额；不介入项目内自动流、采源绑定的日常修改。

02

项目入驻

定位：把一个项目从 0 配到「可以开干」——项目级一次性配置（同一套菜单日后仍可改，但心智上算入驻完成态）。

涉及菜单

项目底座（一次性）

  • 项目列表 · 创建/进入
  • 基本信息与自动流
  • 水印 · 文章模板
  • CMS 账号
  • 外站发布对接（项目可用站）

接入与权限

  • 技术接入 （新 · 待技术细化）
  • 接入向导 / 密钥 / 文档
  • 可选功能开通
  • 账号与授权（建号、勾功能）

用户流程（首次）

  1. 首次登录（账号已有；自助注册另议）
  2. 创建项目，填写基本信息
  3. 配自动流：是否自动转编辑、是否自动发布及 CMS 账号
  4. 配水印、文章模板
  5. 添加并测通 CMS；按需配外站底座
  6. 技术接入联调（占位，待技术）
  7. 开通本项目需要的可选功能
  8. 创建业务账号并按功能/合集授权、绑项目

自动流（重点字段，非全表）

项目名 / CMS 项目码 · 采集自动流开关（采完→自动转编辑）· 自动发布开关与 CMS 账号。水印位置、模板内容、CMS 登录与测连。

交界：入驻完成后进入「业务配置」配采源；无 Userbot 也可先只走网站采集。底座菜单与配置模块可见重叠——区别是时机与变更频率，不是两套页面。

03

业务配置

定位：随业务变化随时调整的配置——采源、账号侧 TG 资产、出口策略等；让「料进得来、出口接得上」。

涉及菜单（两个独立采源能力）

账号资产

  • Telegram / Userbot · 登录
  • 拉取频道 / 加入频道

项目内 · 网站采集（独立功能）

  • 网站采集配置
  • 网站采集记录

项目内 · TG 采集（独立功能）

  • 站点绑定（绑本项目或外站）
  • 采集模式 / 预筛选 / 历史扫描
  • 开始 / 停止监听

用户流程

  1. （可选）账号下添加 Userbot 并加入频道——没有也可只用网站采集
  2. 进入当前项目
  3. 配网站采集：链接、频率、判重、关联外站
  4. 和/或 TG：从账号已加入频道中选择 → 绑定本项目 → 填采集参数 → 开监听
  5. 按需调整外站推送策略（自动 vs 待人工）
  6. 系统开始拉料；素材归属当前项目

TG 绑定（重点，非全字段）

选频道 · 绑定目标（本项目 / 外站二选一）· 判重 · 采集模式（消息/评论区/文件机器人）· 预筛选（浏览量/互动/关键词）· 开监听。公共池路由为例外，不与专属绑定混为一谈。

交界：向上消费入驻完成的项目底座；向下把可用素材送进运营。一账号多项目 = 权限范围，不是账号级共享料池。

04

业务运营

定位：日常待办与三条主线分发；人只在系统断点上场。理想态可走向「配置 + 审核即可发」。

涉及菜单

工作台与主链路

  • 工作台（统计+待办）
  • 主链路·素材审核
  • 采集异常 · 流水线
  • 文章 · 修片 · 外站发布任务

互动（可选，开通后）

  • AI 评论生成 / 审核
  • 用户 / 社区帖评
  • 外站评论审核

系统自动段（流程重点）

拉取 → 筛选 →（待审才）人审 → 媒体处理 → AI 生成正文（TG 分发分支不经此步）→ 按绑定走分支。

用户流程 · 三条分支都是主线

  1. 打开工作台，按待办处理（审核 / 失败 / 待推送等）
  2. 自动流开：可跳过人工编辑直达发布；关：二次编辑 / 修片后确认
  3. 按项目绑定进入对应分发分支

① CMS

上传自有后台 → 已创建。发文审多在站外（虚线）。

② 外站

自动推送，或停在待人工推送后点推送/重试。

③ TG 分发

按路由到频道；不经 AI 生成正文；未分发回异常处理。

交界：主链路审核 ≠ AI/社区审核。反馈为全局浮层，不算运营菜单；处理在方舟 Admin。
