调研背景

方舟技术侧分析发现，约 2026-10-20 至 10-31 期间，平台使用频率有所下降。此前数据侧已有采用率口径说明与下降拆解（见 方舟文章采用率说明与下降原因-20261031.html）：当天采用率从 10/01–10/19 的约 47.7% 降至 10/20–10/30 的约 31.4%，其中一部分来自转编辑时段后移，另一部分集中在少数账号「转得多、发得少」。

在数据结论之上，产品对数据变化最明显的运营做了一对一 / 小范围访谈，核实用量下降是否来自方舟故障，并顺带收集使用卡点与新需求。11-03 先访路飞、探花团队、黄今；11-04 补访数据侧 B 类积压账号「今日吃瓜 · 双喜」。本报告只整理「原因」与「需求」两部分，不重复展开日报算法与逐日图表。

总判断：主访三组的下降，主因都是业务侧人力、搭工作流挤占时间或效果顾虑，不是方舟核心链路大面积故障。补访双喜则更多暴露「采集记录 / 素材管理」认知与列表体验问题，会拖慢转编辑效率。去水印 / 去广告偶发失败、风控误卡、视频封面难改、素材列表改版等，是明确需要开发跟进的诉求。

一、为什么最近使用频率 / 转编辑 / 采用率下降

1.1 受访对象一览

对象 相关项目 / 账号 现象 主因归类 是否平台故障
路飞 蜜桃网 · 路飞 近期转素材 / 使用频率下降；使用时间更偏晚上 近期在搭工作流，处理素材变慢；机器人刚搭好，正在清积压 否
小帅及探花团队 五幺探花 / 51探花 10/20–10/30 探花文章采集与使用率下降 运营一部人员减少；手搓与 A 剧宣发占时 否

双喜（补访） 今日吃瓜 · 双喜 数据侧属「转得多、发得少」积压号；反馈采集 / 素材管理难用 切页丢位置；采集记录与素材管理状态难辨；每页条数少、不可用多、翻页慢 非故障，属体验与认知

1.2 路飞（蜜桃网）

访谈时间：2026-11-03 15:51–15:59。

  • 近期主要精力在搭建自动转发机器人（内容自动转发到采集频道），搭工作流期间处理素材的速度变慢，转编辑随之减少。
  • 机器人最近才搭好，当前阶段在清理此前积压的素材。
  • 结论：用量下降来自搭工作流挤占时间、处理变慢，以及随后清积压，不是方舟功能或效果突然变差；也不是「已被机器人替代所以不用方舟」。
  • 顺带确认：视频里广告 / 水印偶发未去掉，属于长期偶发问题，近期比例没有明显变高；技术难度高，此前未专项处理。路飞曾提过希望增加手动删除能力。

1.3 小帅 / 灵灵 / 浪子 / 柳柒月（51探花）

访谈时间：2026-11-03 16:06–16:38。

  • 探花侧采集与使用率下降，主要因运营一部人员调整、人数减少。
  • 同期「手搓」与 A 剧宣发任务占用大量时间，挤压方舟使用。
  • 结论：非平台故障；产能与任务优先级变化导致用量下行。
  • 团队对文案能力使用较少：生成文案较乱，多数只用方舟做视频和图片，文案再人工重写。这解释了「有转编辑 / 处理，但文案链路采用感不强」的一类体感，不等于转编辑链路坏了。

1.4 黄今（慧姐账号）

访谈时间：2026-11-03 17:17–17:23。

  • 确认近期很少使用转编辑。
  • 主因一：怀疑 AI 处理水印会影响 SU。
  • 主因二：AI 去水印效果不佳；尤其移动水印，处理后后方背景会被大规模模糊。
  • 固定水印用方舟去除，对方反馈效果相对较好。
  • 黄今一方正在排查发帖与收入是否相关（当天与次日重点看收入是否上升）；有结论后同步产品，再决定后续优化优先级。

1.5 双喜（今日吃瓜 · 补访）

访谈时间：2026-11-04 11:42–12:02。数据报告里双喜自 10-21 起转编辑、48 小时采用偏低、待编辑积压较多，故补访。

  • 切换页面后列表未留在原位置，回看不便。
  • 采集记录与素材管理状态显示混乱：素材是否已采集、是否已转编辑难以一眼判断；素材管理每页条数少、不可用素材多，翻页效率低。
  • 产品当场澄清：采集记录只是记录，内容最终进素材管理；日常应直接在素材管理用顶部状态筛选（如「可使用」），筛后基本都可转编辑；转编辑与采集源无关，水印由转编辑时选的项目配置决定。
  • 采集侧建议尽量用外部站点，不建议采公司内部站；双喜可提供外站到方舟群，由技术验证配置。
  • 结论：本场未指向方舟核心故障；主要是列表体验与模块认知问题，会拖慢「转 → 发」效率，与数据侧积压现象可对照看。素材管理改版（每页条数、滑动、总条数等）已在推进。

1.6 对数据侧结论的补强

  • 数据报告里的「晚发 / 积压」在业务访谈里能对上：路飞因搭工作流处理变慢、机器人刚就绪正在清积压；探花侧人力与宣发挤占；并非统一的平台宕机。
  • 黄今这类是「效果顾虑导致少用」，会直接压低转编辑量，值得产品与算法优先响应，而不是只看采用率分母。
  • 双喜这类是「会用但费劲」：状态与列表体验不清，容易多点采集记录、难筛可转素材，放大积压感；培训 / 代教需把「以素材管理 + 状态筛选为主」讲清楚。
  • 已上线能力（自定义提示词、自定义封面、文案链接）已在访谈中向运营宣导；路飞、小帅团队将试用反馈，短期不构成用量下降原因，而是后续回升抓手。

二、访谈中收集的需求与问题（给开发）

下列条目已去重归并。状态分为：新需求、已知问题排查、效果优化、已上线待验证。优先级为访谈侧紧迫感，非正式排期结论。

编号 类型 需求 / 问题 来源 建议下一步
R-01 新需求

视频广告 / 水印偶发去除失败时，提供人工介入能力（如手动框选删除、局部擦除），避免整条链路只能「全自动或放弃」。

路飞此前已提过；本次再次确认该痛点仍在。

 路飞 评估可行性与交互落点（文章编辑 / 素材处理）
R-02 排查

部分视频片头仍残留「杏八」「汤芯」类广告，疑似既有去广告逻辑未生效。

需浪子整理样例素材，经组长转交后排查规则 / 模型覆盖。

 浪子 · 探花 收样例 → 复现 → 修规则或补覆盖
R-03 排查

素材文案 / 标题等含「萝莉」关键词时被卡住，运营认为属于误伤。

需浪子私发被卡内容，产品 / 风控核对命中规则。

 浪子 · 探花 核对词表与拦截策略，区分硬拦截 / 可审放行
R-04 新需求

自定义视频封面：现状视频封面跟随文章封面，难以单独修改；希望支持独立配置视频封面。

已定方案（重构 RF-01）：① 项目配置可选「文章封面 / 视频首帧 / 随机抽帧」；② 文章编辑内可单独上传替换视频封面。

 探花团队 见重构优化清单 RF-01
R-05 效果优化

移动水印去除时，避免对水印后方背景做大面积模糊；当前「去不干净 + 糊一片」是黄今侧少用转编辑的直接原因之一。

 黄今 算法 / 水印服务专项；对比固定水印路径（对方认可固定水印效果）
R-06 新需求

去水印处增加更多选择：现仅一个独立开关，改为固定 / 移动两类策略交叉配置。

已定方案（重构 RF-02）：移动水印 = 去水印 / 视频翻转 / 不去水印；固定水印 = 去水印 / 不去水印。项目级交叉配置，减少外部工具二次处理。

 黄今 见重构优化清单 RF-02
R-07 效果优化

通用去水印 / 去广告偶发失败：长期存在，近期比例未见明显升高，但运营感知强；技术难度高，需持续优化，短期不承诺「彻底干净」。

 路飞 · 探花 · 黄今 持续优化；与 R-01 人工兜底互补
R-08 体验反馈

AI 文案生成质量不稳 / 较乱，团队多用视频与图片能力，文案常整段重写 → 文案相关功能使用率低。

已引导试用「自定义提示词」（可与模板提示词叠加：先模板再自定义优化；文章管理头部也可贴提示词重生成或改当前正文）。待运营对比方舟与 G 站效果后回收反馈。

 探花团队 等试用反馈再决定模板 / 默认提示词是否调整
R-09 本期不做

素材管理 / 相关列表：切换页面或返回后，保留原先浏览位置（滚动位置 / 页码）与筛选条件。

产品取舍：整页刷新难自然保留滚动；每页提到 100 后成本下降。本期忽略。若以后做，优先「筛选 + 页码进 URL」。

 双喜 不进重构本期
R-10 体验优化

素材管理列表效率：增大每页条数、展示总条数 / 总页数。

已定方案（重构 RF-03）：每页最多支持 100 行；展示全部页数与全部内容数。

 双喜 见重构优化清单 RF-03
R-11 认知 / 引导

采集记录与素材管理状态易混淆：运营难以判断「是否已进素材库 / 是否已转编辑」。产品口径已明确——采集记录只作记录，日常在素材管理用状态筛选（如可使用）操作；转编辑与采集源无关，水印跟所选项目配置。

问题含代教未讲清操作逻辑；除 UI 状态表达外，需补培训话术 / 空态或模块说明。

 双喜 UI 状态文案排查 + 运营培训材料补一节

2.1 已宣导、本期不算新需求的能力

  • 自定义提示词：项目设置 → 文章模板 / 文案生成提示词管理；可仅用自定义，或与模板提示词同时开启。
  • 自定义封面：本地或素材库选图，调整位置与大小后组合封面（文章侧）。
  • 文案链接配置：项目内配置关键词与链接，命中后自动加链。
  • 转编辑与采集源无关、水印由转编辑所选项目决定（双喜场澄清，属口径说明）。
