---

## 1. 目标（不变）

帮用户和运营更好地：

1. **找瓜**——站里有没有、相关还有啥  
2. **丰富瓜**——已有瓜能不能玩厚（站队、投票等）  
3. **提心愿瓜**——没有就喊出来，热度起来再变成真瓜  

模块底层：轻贴吧式信息流，里面是**不同类型的帖**（心愿、站队投票、对抗式等），不是单一许愿表。

---

## 2. 三条主回路（按这个设计）

对应关系图上的三条路：**有存量 → 丰富；AI 再挖仍属找；没有 → 提心愿**。

### 主回路 ① 找瓜

人带着关键词或好奇进来，先把**存量瓜**递到面前。

```text
搜索 / 从入口进模块瞎逛
        ↓
   有结果 → 进详情看瓜（可转丰富瓜）
        → 结果不满意也可「去提心愿」
   无结果 → 直接「去提心愿」（带上搜索词）
```

**子回路 ①-a · 搜索接提心愿**（不经 AI）

- 无结果：主 CTA 直接去发心愿。
- 有结果：列表旁/底仍给「去提心愿」，防止结果不对味只能干瞪眼。

AI 放在**模块内部**「吃瓜 Agent」，不插在搜索失败路上：一次提问 → 汇集站内相关正文/图/求瓜/投票/短剧集数 → AI 理清脉络（去重、串时间线），不是返回搜索列表。

---

### 主回路 ② 丰富瓜

瓜已经在了（或事件正热），用互动把瓜玩厚、把人留住，并反哺选题。

```text
详情页里的瓜 / 模块里已有相关帖
        ↓
   开或进「站队投票」类帖（含对抗式：两边说法/两边立场）
        ↓
   用户选边、看比例、（可选）跟风 agitate
        ↓
   热度可见 → 运营可据此做衍生盘点 / 加码内容
```

说明：

- **站队投票、对抗式** = 同一类玩法下的**帖子类型**（题干 + 选项/两边阵营），不是另起一个产品。
- Demo 里详情页要能**顺手摸到**这类玩法（例如「去站队」），模块内也能发、能投。

---

### 主回路 ③ 提心愿瓜（最主的一条）

没有想看的 → 说出来 → 大家帮腔 → 圆成真瓜 → 挂回来。

```text
模块入口 / 搜不到接力 / 详情里「没有我想看的」
        ↓
   发心愿帖
        ↓
   别人加油（热度）
        ↓
   同艺人/同事件用「标签」聚在一起（心愿合并的轻做法）
        ↓
   运营按热度 + 标签产瓜
        ↓
   心愿「已安排」挂回正文；正文也可回标「来自心愿」
```

**子回路 ③-a · 标签聚合（原「心愿合并」）**

- 不做复杂「合并帖」流程也行：同一艺人、同一事件打**同一个标签**，列表/筛选按标签聚合看热度。
- Demo 里心愿卡带标签，模块内可按标签点进聚合。

**子回路 ③-b · 圆梦回响**

```text
高热心愿 → 真瓜上线 → 心愿卡变「已安排」可点进详情
        → 详情露出「来自心愿」→ 激励再喊、再加油
```

## 3. 帖子类型（玩法零件，先点名）

| 类型 | 挂在哪条主回路 | 一句话 |
| --- | --- | --- |
| 心愿帖 | ③ 提心愿瓜 | 我想看某某；可加油；可打标签 |
| 站队投票帖 | ② 丰富瓜 | 你站谁 / 选哪边；选项投票 |
| 对抗式帖 | ② 丰富瓜 | 站队投票的一种形态：两边对立说法/立场 |
| （可往后加） | — | 纯讨论等，Demo 可不做 |

AI：放在**模块内**「问一问」——帮找瓜、送进站队、或把「没有」收成心愿草稿；不插在搜索失败路上。

## 4. Demo 需要有哪些模块

按「页面/场」铺，每场接到三条主回路上。

### 4.1 搜索

- 有结果：列表可进**详情**；并提供「去提心愿」（结果不满意也能喊）。
- 无结果：直接「去提心愿」（带上搜索词），不经 AI。
- 体现主回路 ①，并接到 ③。

### 4.2 详情页

- 正常看瓜（正文示意即可）。
- 接 **丰富瓜**：相关站队/投票入口（已有则进入投票，没有可用「官方已开票」示意卡）。
- 接 **提心愿 / 圆梦**：若该文来自心愿，露出「来自心愿 #xx」；也可有「没有想看的？去提心愿」。
- 体现主回路 ②，并回声 ③-b。

### 4.3 模块入口

- **常驻入口**示意（导航占位即可，具体一级/二级会上再定）。
- 从搜索无结果、详情「去提心愿 / 去站队」也能进模块。
- 进门后落到模块首页（信息流）。

### 4.4 模块内部

| 块 | Demo 要能点到什么 | 主要回路 |
| --- | --- | --- |
| 信息流首页 | 混合流：心愿帖 + 站队/对抗帖；最热/最新；按标签点进聚合 | ②③ |
| 发心愿 | 登录后发帖；可选标签（艺人/事件）；提交后待审/上墙示意 | ③ |
| 加油 | 登录后给心愿加一票热度 | ③ |
| 发 / 参与站队投票 | 题干 + 选项（含对抗两边）；登录投票看比例 | ② |
| 问 AI | 输入好奇点 → 模拟命中站内链 或 未命中转发心愿草稿 | ①→③ |
| 已安排 | 心愿卡状态可点进详情（圆梦） | ③-b |
| 我的帖子 | 登录后看自己发的心愿/投票状态（示意） | 辅助 |
| 标签聚合页 | 同一标签下的心愿（+ 相关投票可一并露出） | ③-a |

**登录口径（已定）**：仅「发求瓜」要登录；点赞、投票不登录；评论不登录，但要填昵称（本地记住）。

## 5. Demo 页面清单（落地用）

1. **搜索页**（有结果态 + 去提心愿）  
2. **搜索页**（无结果态 + 去提心愿）  
3. **文章详情页**（站队入口 + 来自心愿 + 去提心愿）  
4. **模块入口**（导航占位 → 进首页）  
5. **模块首页**（信息流）  
6. **发心愿**  
7. **站队/对抗投票**（发或参与，至少参与完整）  
8. **问 AI**（模块内，不挂搜索失败路）  
9. **标签聚合**  
10. **已安排 → 回详情**（圆梦一条闭环）  
11. **登录示意**（拦截发/赞/投）  
12. **我的帖子**（可简）

后台审核不必做完整产品，有一张「运营已审过 / 已安排」的示意即可。

视觉：对齐现网 51吃瓜列表——深色底、宽幅长方形封面卡（约宽 20+ / 高 9 比例）、粉系「热门」标签与顶栏结构。

## 6. 评论交互（信息流 + 帖内详情）

只理评论这一块；点赞仍在标题行右上角，不进本表。

### 6.1 两层入口

| 层 | 入口 | 点下去干什么 |
| --- | --- | --- |
| 信息流卡片 | 标题「评论 N」+「查看全部评论」；无评时虚框内另给「去抢首评」 | 进帖内详情 → 全部评论 + 输入框 |
| 帖内详情 | 底部输入框「发送」 | 登录后发评；刷新列表 |

信息流**不**在卡片内直接发评（Demo 先收口到详情页发）。

### 6.2 信息流评论区（对用户不暴露排序规则）

| 态 | 条件 | 左侧 | 右侧 | 下方展示 |
| --- | --- | --- | --- | --- |
| 无评论 | `N === 0` | 评论 0 | 查看全部评论 | 空态「还没人评，来说两句」+「去抢首评」 |
| 有评论 | `N > 0` | 评论 N | 查看全部评论 | 最多 2 条预览（纯用户名+正文+时间） |
| 详情 | 进帖后 | 全部评论（N） | — | 全量列表 + 输入框 |

后台可按「精选优先，否则按新」抽预览。用户不必读懂排序规则：每条左侧用标记表达即可——

| 左侧标记 | 含义 |
| --- | --- |
| 「神评」文字 | 神评（放左边，不用右侧标签） |
| 👍 | 运营精选推上来的 |
| 🔥 | 按热度推上来的 |
| 🕐 | 按时间新推上来的 |

**不再**在正文旁跟「运营精选 / 热门」等文字标签。

## 7. 先记下的方向（不抠细则）

- 三条主回路设计；子回路：搜索接求瓜、标签聚合、圆梦回响。  
- 搜索有结果 / 无结果均可去求瓜；无结果不经 AI。  
- 用户侧命名：**求瓜心愿墙**；按钮「求瓜」/「发布吃瓜心愿」；求瓜帖可**点赞 + 评论**（不可嵌套投票）。  
- **投票是独立帖类型**，仅运营发起；可关联求瓜/内容，也可独立；用户不能发、可参与。  
- 求瓜「合并」→ 用**标签聚合**表达。  
- Demo 四场：搜索、详情、模块入口、模块内部玩法。  
- 出手要登录；通知不做；AI 在模块内；常驻入口要有。  
- 评论四态与按钮位置见 §6。

细则（字数、审核流等）讨论 Demo 时再开，本文不锁。
